## Spacing Scale

Phase 81 uses the approved 4, 8, 16, 24, 32, and 48px subset of the shipped 4px-base scale. HEEx and page CSS reference tokens instead of raw spacing values when a shipped token exists.

| Token | Value | Usage |
|-------|-------|-------|
| `--obpt-space-1` | 4px | Status marker/text gaps, compact metadata, progress labels, timeline marker offsets. |
| `--obpt-space-2` | 8px | Dense table internals, description pairs, step metadata, inline evidence/actions, compact result rows. |
| `--obpt-space-4` | 16px | Narrow page/dialog inset, ordinary component internals, stacked fields, selection summary, action groups. |
| `--obpt-space-5` | 24px | Default surface padding, section separation, explanation-to-action rhythm. |
| `--obpt-space-6` | 32px | Wide page gutter, master/detail and DAG/detail gutter, major section separation. |
| `--obpt-space-7` | 48px | Major showcase/page-story separation only; avoid inside tables, timelines, progress, or evidence rows. |

Exceptions:

- Every interactive control exposes at least a 44px effective target, including row/page selection, pagination, detail links, view toggles, preview, dialog dismiss/submit, fresh-preview recovery, and Audit/Forensics destinations.
- DataTable retains the shipped 32–36px wide/tablet visual row density while controls inside each row retain 44px targets.
- At 320px, page and full-screen dialog inset is 16px; adjacent controls retain at least 8px separation.
- The adaptive-detail breakpoint around `64rem`, the 320px viewport, and 200% zoom are responsive constraints, not spacing tokens.
- Focus uses the shipped outline, offset, and `--obpt-color-focus`; no page-specific focus geometry.
- Only labelled, focusable machine-content regions may scroll horizontally. All other grid/flex children use `min-width: 0`, wrapping, or visibly signalled truncation.

Source: `guides/brand-book.md` D-15; `81-CONTEXT.md` Responsive and Accessible Composition; approved Phase 77–80 spacing contracts.

## Typography

Page-owned typography uses exactly four sizes and two weights. Shipped components retain their approved internal typography.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Dense table metadata / secondary evidence | 13px (`--obpt-font-size-sm`) | 400 (`--obpt-font-weight-regular`) | 1.4286 (`--obpt-line-height-base`) |
| Body / table value / control / event sentence | 14px (`--obpt-font-size-md`) | 400 (`--obpt-font-weight-regular`) | 1.4286 (`--obpt-line-height-base`) |
| Section / result / detail heading | 18px (`--obpt-font-size-xl`) | 600 (`--obpt-font-weight-semibold`) | 1.25 (`--obpt-line-height-tight`) |
| Page H1 | 28px (`--obpt-font-size-page-title`) | 600 (`--obpt-font-weight-semibold`) | 1.25 (`--obpt-line-height-tight`) |

Rules:

- Do not use weights 300, 500, 700, or heavier in page-owned Phase 81 UI.
- Each page has exactly one 28px H1. Section headings are 18px. Component-owned titles retain shipped sizing.
- Counts, attempts, timestamps, progress numerals, page totals, and affected-record totals use sans with `font-variant-numeric: var(--obpt-numeric-tabular)`.
- Mono is scoped to literal complete IDs, modules, dedupe keys, codes, and bounded machine evidence. Status, diagnosis, reason, guidance, counts, provenance, and action copy remain sans.
- Long English, Unicode, emoji, RTL text, and unbroken machine values wrap or use the shipped visible machine-value treatment without reducing primary content below 13px.

Source: `guides/brand-book.md` D-13..D-15; approved Phase 77–80 typography contracts.

## Color

All values resolve through semantic `--obpt-color-*` roles in system, light, dark, and high-contrast themes. Raw hex remains confined to the primitive palette in the token layer.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--obpt-color-surface`, `--obpt-color-text` | Page background, table body, DAG/step narrative, incident evidence, primary prose. |
| Secondary (30%) | `--obpt-color-elevated`, `--obpt-color-overlay`, `--obpt-color-border`, `--obpt-color-border-strong`, `--obpt-color-muted`, `--obpt-color-subtle` | Headers, detail/confirmation shells, chain/evidence sections, historical Audit content, neutral completeness and ownership truth. |
| Accent (10%) | `--obpt-color-accent-solid`, `--obpt-color-accent-bg`, `--obpt-color-accent-border`, `--obpt-color-accent-fg`, `--obpt-color-focus` | Safe selection/current state, list-to-detail navigation, supported native/Forensics/Audit routes, fresh-preview recovery, and keyboard focus. |
| Destructive / danger | `--obpt-color-danger-solid`, `--obpt-color-danger-bg`, `--obpt-color-danger-border`, `--obpt-color-danger-fg` | Lifeline repair execution, genuine failed/error/permission-denied state, and immediate failure requiring attention only. |

Accent reserved for: selected batch/workflow/step/incident, current view and pagination, safe `Review`/`Inspect` navigation, `Open Forensics`, `Open in Audit`, valid fresh-preview recovery, and focus-visible treatment.

Semantic rules:

- Neutral chrome occupies roughly 90% of every surface. No gradients, alarm-card walls, nested-card walls, badge soup, broad status fills, or decorative color.
- Retry preview is warning intent; actual Lifeline remediation execution is danger intent. The action and restrained consequence marker carry intent, not the entire dialog.
- Unified status taxonomy owns batch, job, callback, workflow, step, incident, health, preview, and outcome presentation. Unknown stays explicit neutral, never success.
- Status, severity, progress, provenance, completeness, current versus historical evidence, and ownership are independent visible dimensions.
- Color is always paired with visible text plus icon, shape, border, weight, or programmatic state.

## Cross-Page Information Hierarchy

All three pages render inside `ThemeShell -> AppShell -> main#obpt-main`; do not instantiate another shell.

Shared hierarchy:

1. One H1 and one plain-language introduction.
2. Current read/write support and permission truth.
3. Bounded current scan, progress, or incident view.
4. One selected detail, diagnosis, or `Why blocked?` explanation.
5. The legal next action nearest its consequence and authority boundary.
6. Freshness, completeness, affected scope, and provenance.
7. Immutable technical or Audit evidence.

Shared layout rules:

- Use one semantic DOM tree per page/component at every viewport. CSS and the shipped adaptive controller change geometry; never duplicate tables, details, dialogs, progress, or sensitive evidence for mobile.
- One local decision has one visually primary action. Oban Web, Forensics, Audit, back, and dismiss routes use appropriate secondary treatment.
- Explain before acting. Do not place equal-weight actions above diagnosis, affected scope, non-effects, or authority boundaries.
- Rows are never whole-row click targets. DAG relationships use semantic lists/description structures rather than a canvas-only or pointer-only graph.
- Avoid nested cards. One shared surface may contain semantic subsections separated with dividers.
- Presenters structurally redact and project finite maps before page assigns. Raw domain structs, metadata, exceptions, tokens, and provider maps never enter generic page composition.

Source: `81-CONTEXT.md` Migration Shape and Ownership, Operator Journeys and Safety; approved Phase 79–80 hierarchy contracts.

| Context | Exact contract |
|---------|----------------|
| Reason label | `Reason` |
| Reason hint | `Explain why this action is needed. Do not enter secrets.` |
| Blank reason | `Enter a reason before continuing.` |
| Short Lifeline reason | `Enter at least 8 characters.` |

| Region / state | Visual Contract | Interaction / Truth Contract |
|----------------|-----------------|------------------------------|

## State, URL, History, Focus, and Dialog Contract

| Concern | Contract |
|---------|----------|
| Explicit states | Preserve ready, loading, empty, unavailable, permission denied, error, stale, partial, skipped, failed, drifted, expired, consumed, disconnected, interrupted, resolved, and unknown where applicable. Unknown is neutral/explicit, never success. |
| Loading | Name the resource and apply `aria-busy` to the owning region. No bare spinner, fake progress, or whole-page alarm. |
| URL parity | Preserve all existing Batches status/name/page/detail/back state; Workflows id/step deep links; Lifeline view/incident/target/workflow-step selection. Unknown/incompatible values fail safely and do not broaden queries or authority. |
| History | List-to-detail and step/incident selection retain current push/patch semantics. Back, direct URL, reload, and explicit close produce the same selected truth; breakpoint changes never add history. |
| Selection focus | On list refresh, retain focus when the target remains; otherwise move to the logical list heading or selected-item fallback. Never strand focus in removed markup. |
| Confirmation open | Invoker opens exactly one native modal. Focus starts on the labelled title/consequence, not the destructive submit. Background is inert through native modality. |
| Confirmation close | Escape and safe dismiss work while dismissible and restore the connected invoker or logical fallback. Accepted nondismissible work may disable Escape only while server-owned execution is active. |
| Result focus | Recoverable result focuses its labelled result/recovery heading. Clean success closes and restores focus to the updated action/detail/list fallback. |
| Live messages | Announce useful selection/load completion, preview readiness, execution start, and final result only. Do not announce every progress tick, member, callback, step, or evidence row. |

## Interaction and Accessibility

- Use semantic headings/sections, native tables/captions/header cells, ordered/unordered lists, description lists, links, buttons, forms/labels/hints/errors, `time`, native `progress`, disclosure, and native dialog. Do not add ARIA grid, canvas-only DAG, row-click, menu, or spreadsheet semantics.
- Each page has one H1 and logical heading/landmark order. Every table has an accessible caption. Workflow dependencies and Lifeline history remain intelligible without layout or color.
- Every interactive element is keyboard reachable/operable with visible, unobscured focus in system, light, dark, and high-contrast themes.
- Row/page selection, detail/review links, pagination, view toggles, preview, dialog controls, recovery, and evidence destinations meet the 44px effective target.
- Color alone never carries batch/job/callback/workflow/step/incident status, selection, health, progress, blocker severity, outcome, provenance, completeness, or current-versus-historical meaning.
- Batch member selection exposes per-row names, page scope, checked/mixed state, eligible exclusions, and selected count. Disabled members retain a visible reason.
- Progress exposes native current/max plus visible completed/total and percent. Do not announce animated/intermediate ticks.
- `Why blocked?` uses a labelled region and complete human explanation before machine evidence or action.
- Form errors remain associated by invalid/described-by relationships. Invalid reason remains visible. Submit focuses error summary or first invalid field, not every keystroke.
- Dialog focus is contained and restored; Escape closes while dismissible. Reauthorization races produce persistent recovery, not disappearing errors.
- Axe must report zero critical/serious findings, but connected evidence must also prove keyboard selection, direct/deep links, focus containment/restore, Escape, Back, authorization race, 320px reflow, 200% zoom, reduced motion, sparse announcements, and confidential DOM absence.

## Security, Privacy, and Authority Presentation

- Parent LiveViews authorize page/resource/action access server-side. Disabled controls, hidden CSS, and preview presence are never authority.
- Batches and Lifeline authorize before preview and reauthorize target(s) immediately before execution. Lifeline remains the only repair execution authority. Workflows remains read-only diagnosis.
- Missing and unauthorized resources use indistinguishable presentation.
- Normalize and structurally allowlist data before page assigns and component rendering. Shared components receive only plain safe maps/scalars.

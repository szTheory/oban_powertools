| Property | Value |

## Spacing Scale

Data-display CSS and components must use existing Powertools spacing tokens or token-backed classes. Do not introduce raw spacing values in HEEx source or component CSS when a token exists.

| Token | Value | Usage |
|-------|-------|-------|
| `--obpt-space-1` | 4px | StatusPill icon/text gap, table sort indicator gap, compact timeline rail offsets, code inline padding. |
| `--obpt-space-2` | 8px | Dense table cell vertical rhythm, dense DataTable cell horizontal padding, pill padding, toast icon gap, KeyValue row gap, compact EmptyState spacing. |
| `--obpt-space-4` | 16px | Default card/table wrapper padding, DataTable cell horizontal padding at tablet/wide, timeline item internal gaps, MetricCard padding, Toast/Flash padding. |
| `--obpt-space-5` | 24px | Section separation, EmptyState block padding, Timeline group spacing. |
| `--obpt-space-6` | 32px | Wide data-story grouping and major layout gutters only. |
| `--obpt-space-7` | 48px | Major showcase spacing and hit-target derivations; avoid inside dense tables. |
| Phase maximum | 64px | Page-level whitespace only; no Phase 77 component uses 64px internally. |

Exceptions:

- DataTable rows use a calm dense target: 32-36px visual row height at tablet/wide. Interactive cells, sortable headers, pagination buttons, row checkboxes, copy buttons, and dismiss buttons must expose at least a 44px effective hit target.
- The 320px viewport is a required test target, not a spacing token. Tables must switch to stacked/card rows at 320px with no page-level horizontal scroll.
- Bounded code, args, JSON, and stacktrace blocks may scroll internally. Other data components must wrap, truncate visibly, or stack instead of creating horizontal page overflow.
- Progress bars use a minimum 8px track and must keep visible text adjacent to the bar; the bar alone is not sufficient status.
- Focus geometry uses the existing 2px tokenized focus outline/offset and `--obpt-color-focus`; do not create data-component-specific focus rings.

Source: `guides/brand-book.md` D-15; `assets/oban_powertools/tokens.css`; `.planning/REQUIREMENTS.md` DATA-03 and A11Y-03; Phase 74/75/76 UI-SPEC spacing contracts.

## Typography

Use exactly these data-display roles and only weights 400 and 600.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Dense row / code value | 13px (`--obpt-font-size-sm`) | 400 (`--obpt-font-weight-regular`) | 1.4286 (`--obpt-line-height-base`) |
| Body / table value | 14px (`--obpt-font-size-md`) | 400 (`--obpt-font-weight-regular`) | 1.4286 (`--obpt-line-height-base`) |
| Header / label / status | 13px (`--obpt-font-size-sm`) | 600 (`--obpt-font-weight-semibold`) | 1.25 (`--obpt-line-height-tight`) |
| Metric value / section heading | 18px (`--obpt-font-size-xl`) | 600 (`--obpt-font-weight-semibold`) | 1.25 (`--obpt-line-height-tight`) |

Rules:

- Do not introduce 300, 500, 700, or heavier weights in Phase 77 data-display UI.
- Numeric metrics, counts, attempts, percentages, and timestamps use sans text with `font-variant-numeric: var(--obpt-numeric-tabular)`.
- Mono is reserved for machine values: IDs, hashes, queue literals, module/worker names, cron expressions, args/JSON, stacktraces, and inline code. Ordinary counts and status labels stay sans.
- Long IDs truncate in the middle when displayed in compact cells; the full value must be available through a copy affordance or an explicit expanded view. Do not put sensitive or redacted values in `title`.
- Worker/module names preserve the trailing segment, for example `...Workers.SendEmail`, and remain readable at 320px and 200% zoom.

Source: `guides/brand-book.md` D-13..D-15; `assets/oban_powertools/tokens.css`; `.planning/REQUIREMENTS.md` DATA-03.

## Color

Components reference semantic `--obpt-color-*` roles only. Raw hex remains confined to the token layer.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--obpt-color-surface`, `--obpt-color-text` | Table body, detail panels, timeline body, args/code text, EmptyState content, ordinary Toast/Flash content. |
| Secondary (30%) | `--obpt-color-elevated`, `--obpt-color-border`, `--obpt-color-border-strong`, `--obpt-color-muted`, `--obpt-color-subtle` | Table headers, row separators, stacked-row cards, code block backgrounds, timeline rails, MetricCard shells, neutral empty/loading/unavailable states. |
| Accent (10%) | `--obpt-color-accent-solid`, `--obpt-color-accent-bg`, `--obpt-color-accent-border`, `--obpt-color-accent-fg`, `--obpt-color-focus` | Active sort indicator, selected page/row state, safe empty-state CTA, safe copy/link affordance, and keyboard focus. |
| Destructive | `--obpt-color-danger-solid`, `--obpt-color-danger-bg`, `--obpt-color-danger-border`, `--obpt-color-danger-fg` | Error states, danger StatusPill values, destructive/error Toast/Flash, and failed redaction/policy fallbacks only. |

Accent reserved for: active sort state, current pagination state, safe EmptyState CTA, safe copy/link affordance, selected row/control state, and focus-visible treatment. Accent must not be used for status meaning, warnings, success, danger, broad table chrome, decorative fills, or every interactive element.

Semantic tones:

| Tone | Token family | Reserved for |
|------|--------------|--------------|
| `neutral` | surface/elevated/border/muted | Available, pending, scheduled, bridge-only, unknown, ordinary metadata, empty/loading/unavailable structure. |
| `info` | `--obpt-color-info-*` | Running/executing, claimed, ready/runnable, active but non-problem state. Never use info for primary actions. |
| `success` | `--obpt-color-success-*` | Completed, delivered, resolved, consumed, ok/success, healthy terminal state. |
| `warning` | `--obpt-color-warning-*` | Retryable, waiting, paused, needs review, stale, drifted, ambiguous, callback failure, exhausted, output unavailable/expired. |
| `danger` | `--obpt-color-danger-*` | Cancelled, discarded, deleted, failed, error, expired terminal failure, permission-denied/error states. |

Color is never the sole signal. StatusPill, progress, toast, error, permission-denied, unavailable, and selected-row states must include visible text plus one non-color channel: icon, shape, position, `aria-*`, or explicit label.

Source: `guides/brand-book.md` D-05, D-07..D-12; `assets/oban_powertools/tokens.css`; Phase 74 status primitive contract.

## Copywriting Contract

Data-display copy uses the brand voice: fact plus next action, plain recovery guidance, and support-truth boundaries.

| Element | Copy |
|---------|------|
| Primary CTA | `Refresh data` |
| Empty state heading | `No rows match the current filters` |
| Empty state body | `Clear filters or widen the time window.` |
| Error state | `Data did not load. Retry the request or check the host logs.` |
| Destructive confirmation | None in Phase 77. Destructive confirmations remain Phase 78/page-owned work. Error and danger toasts may report outcomes but must not execute mutations. |

Required state copy:

| State | Required copy pattern |
|-------|-----------------------|
| Loading | `Loading {resource}`. Example: `Loading job table`. No bare spinner text. |
| Empty | Fact plus next action. Example: `No jobs match the current filters. Clear filters or widen the time window.` |
| Unavailable | `Data unavailable. {specific reason or boundary}.` |
| Permission denied | `{Action or data} unavailable - requires {role or permission}.` Disabled controls remain visible when the reason matters. |
| Error | `{Resource} did not load. Retry the request or check the host logs.` |
| Redacted | `Redacted at enqueue` for enqueue-time field redaction; `Hidden by display policy` for host policy redaction. Do not imply Powertools can reveal host-hidden data. |
| Success toast | Confirm what happened in Powertools vocabulary. Example: `Retry requested. Job re-enters the default queue.` |
| Error toast | Name the failed operation and recovery path. Example: `Callback retry did not start. Refresh the batch and preview the retry again.` |

Rules:

- Status labels use humanized sentence/title case, not raw snake_case. Example: `callback_failed` renders as `Callback failed`.
- Table and timeline labels use one term per concept from the brand glossary: Cancel, Discard, Delete, Retry, Pause, Resume, Job, Worker, Blocked, Preview, Repair, Reason, Audit log, Limiter.
- Toast/Flash copy must not say "fixed", "done", or "succeeded" unless the stored Powertools result proves that outcome.
- Do not use `Something went wrong`, `An error occurred`, `N/A`, or icon-only messages.

Source: `guides/brand-book.md` D-16..D-21; `.planning/REQUIREMENTS.md` COPY-01..02 and DATA-03.

## Data Component Contracts

Preferred module: `ObanPowertools.Web.Components.DataDisplay`. Pure presentation helpers may live in a supporting module such as `ObanPowertools.Web.StatusTaxonomy`, but the mapping must be shared and tested.

| Component | Visual Contract | Interaction / Accessibility Contract |
|-----------|-----------------|--------------------------------------|
| DataTable | Token-backed table with explicit header, body, caption/summary, optional toolbar slot, row key, row count, pagination summary, and state slot. Tablet/wide rows are 32-36px dense; headers use elevated surface and visible separators. | Render semantic `<table>` at tablet/wide. Sortable headers are real buttons inside `<th scope="col">` and set truthful `aria-sort` on the sorted column. Parent LiveViews own sort state/events. No ARIA grid role. |
| DataTable stacked row | At 320px, each row renders as a compact stacked/card layout using the same row data and visible column labels. No page-level horizontal scroll. | Each stacked cell exposes the original column label as visible text or `dt`/`dd` semantics. Row selection remains a labelled checkbox with a 44px hit target. |
| DataTable states | Loading uses named skeleton rows; empty, error, unavailable, and permission-denied use the shared EmptyState pattern inside the table region, not an absent table. | Loading region uses `aria-busy="true"` and a named status. Error uses `role="alert"` only for immediate failures. Empty/unavailable/permission denied are readable without color. |
| KeyValue / DescriptionList | Render compact `<dl>` pairs with labels at 13px semibold and values at 14px/13px. Machine values may use mono and middle truncation. | Preserve `dt`/`dd` semantics. Long values use `min-width: 0`, wrapping, visible truncation, copy affordance, or explicit expansion. |
| StatusPill | Wrap the Phase 74 primitive `status_pill`; do not use raw Badge for domain state after this phase. All pills include visible label, tone, icon, and `sr_prefix` such as `Job state`, `Batch status`, or `Workflow step state`. | Non-interactive by default. It must not look clickable and must suppress action attrs. Color is paired with visible label and icon/shape. |
| Timeline | Ordered event log with timestamp, title, actor/source when available, status pill where useful, and optional detail/code block. Rail and markers use neutral/status tokens only. | Render ordered list semantics, not a layout-only div chain. Timestamps remain readable with tabular numerics. Long stacktraces/details use bounded CodeBlock. |
| ProgressBar | Token-backed track/fill with adjacent label, numerator/denominator, and percent. Width is clamped 0-100. Ordinary progress uses accent; stateful progress may use success/warning/danger only when the status text says why. | Use `role="progressbar"` with `aria-valuemin="0"`, `aria-valuemax`, `aria-valuenow` when determinate, and an accessible label. Unknown progress uses text such as `Progress unavailable`, not a fake percentage. |
| MetricCard | Compose existing `surface/card` and `stat` treatment: label, value, optional trend/status text, optional help tooltip. No nested card stacks. | Numeric values use tabular sans. Trend direction/severity includes text, not color alone. Metrics do not become buttons unless rendered as an explicit Link/Button. |
| CodeBlock | Mono 13px block for JSON, args, stacktraces, cron expressions, and raw payloads. Bounded internal overflow is allowed; page-level overflow is not. | Use `<pre><code>` for code/literal blocks. Provide a label/caption when context is not obvious. Copy affordance is optional and must not expose redacted data. |
| ArgsViewer | Shared renderer for `DisplayPolicy.render_job_field/3`, workflow results, callback payloads, job meta, and error payloads. It owns `:raw_json`, `:string`, and `:fallback` display consistently. | Redaction is rendered only through the shared RedactedValue/overlay component. Host policy strings/maps are respected; Powertools does not overlay them again. |
| RedactedValue | Compact token-backed mark for `Redacted at enqueue`, `Hidden by display policy`, and `[redacted]` fallback. It is neutral/warning-weight, not danger unless policy rendering itself failed. | Never place original sensitive value in DOM, tooltip, title, data attribute, or copy buffer. Include screen-reader text naming why the value is hidden. |
| EmptyState | Neutral/elevated block with heading, body, optional safe CTA, and optional small status glyph. No decorative illustration requirement. | Heading plus body are always present. CTA uses Button/Link semantics matching its action. Empty state is not used for loading or permission denied. |
| Toast / Flash | Token-backed flash stack for info/success/warning/danger. It uses restrained surface, clear icon/text, optional close button, and no broad color fill. | Success/info use polite status semantics; warning/danger/error use alert semantics only when immediate attention is needed. Close button has accessible name and 44px hit target. |

API rules:

- Use `attr/3`, `slot/3`, closed values, and explicit assigns. Permit caller `id`, supported `phx-*`, `aria-*`, and `data-*`; filter or reject caller `class` and `style`.
- Components own semantics, visual variants, empty/loading/error rendering, data-state wrappers, and safe formatting. Parent LiveViews own data fetching, authorization, sorting, pagination, selection state, mutation events, and URL state.
- Do not add component-level global selectors, host selectors, inline styles, raw hex, raw component spacing where tokens exist, or JavaScript dependencies for sorting/table behavior.
- DataTable does not introduce client-side virtualization in Phase 77. For thousands of rows, parent surfaces paginate or provide bounded row windows while the component displays row count and stable keys.

Source: `.planning/REQUIREMENTS.md` DATA-01..04; existing primitive/form API rules; `lib/oban_powertools/runtime_config.ex`; `test/support/showcase_catalog.ex`.

## Status Taxonomy Contract

One shared status taxonomy must map every known Oban/Powertools state to StatusPill presentation data. Pages must not keep local helpers such as `state_badge_tone/1`, `status_badge_class/1`, `severity_badge_class/1`, or raw tone maps after they migrate to Phase 77 components.

Status presentation shape:

```elixir
%{
  label: "Retryable",
  tone: :warning,
  icon: :alert,
  sr_prefix: "Job state"
}
```

Tone/icon rules:

| Tone | Icon | Meaning |
|------|------|---------|
| `neutral` | `dot` | Queued, pending, scheduled, available, ordinary metadata, unknown, bridge-only. |
| `info` | `info` | Active/running/executing/claimed/ready/runnable states that need context but are not failures. |
| `success` | `check` | Completed, delivered, resolved, consumed, healthy, ok, success. |
| `warning` | `alert` | Retryable, waiting, paused, needs review, stale, drifted, exhausted, callback failed, output unavailable/expired, ambiguous. |
| `danger` | `alert` | Cancelled, discarded, deleted, failed, error, expired terminal failure, permission denied. |

Required mapped values:

| Domain | Values |
|--------|--------|
| Oban job state | `available` neutral; `scheduled` neutral; `executing` info; `retryable` warning; `cancelled` danger; `discarded` danger; `completed` success. |
| Batch status | `inserting` info; `executing` info; `exhausted` warning; `insert_failed` warning; `callback_failed` warning; `completed` success. `all` is filter copy only and renders neutral if displayed. |
| Batch member / Oban member state | `available` neutral; `scheduled` neutral; `executing` info; `retryable` warning; `failed` danger; `discarded` danger; `cancelled` danger; `completed` success. |
| Callback outbox status | `pending` neutral; `claimed` info; `failed` danger; `delivered` success. Expired leases render as `Lease expired` warning while preserving stored status text where needed. |
| Workflow state | `pending` neutral; `available` neutral; `running` info; `cancel_requested` warning; `completed` success; `failed` danger; `cancelled` danger; `expired` danger. |
| Workflow step state | `pending` neutral; `available` neutral; `retryable` warning; `executing` info; `running` info; `awaiting_signal` warning; `completed` success; `ok` success; `success` success; `cancelled` danger; `discarded` danger; `deleted` danger; `failed` danger; `error` danger; `expired` danger. |
| Workflow await status | `waiting` warning; `resolved` success; `expired` danger. |
| Workflow signal status | `recorded` neutral; `consumed` success; `late` warning; `unmatched` warning; `ambiguous` warning. |
| Workflow result / job record status | `ok` success; `completed` success; `success` success; `failed` danger; `error` danger; `redacted` warning when used as display status. |
| Lifeline preview status | `ready` info; `drifted` warning; `expired` danger; `consumed` success. Legacy `pending` maps to `ready`; legacy `executed` maps to `consumed`. |
| Lifeline incident/archive status | `active` warning; `resolved` success; `pending` neutral; `running` info; `blocked` warning; `failed` danger; `completed` success. |
| Cron/operator status | `runnable` info; `waiting` warning; `paused` warning; `ready` info; `skipped` warning; `queued_follow_up` warning; `healthy` success. |
| Limiter/control-plane status | `needs_review` warning; `blocked` danger; `waiting` warning; `runnable` info; `resolved` success; `bridge_only` neutral. |
| Permission/data availability | `permission_denied` danger; `unavailable` warning; `stale` warning; `disconnected` warning; `unknown` neutral. |

Unknown values:

- Unknown state strings render with a humanized label, `neutral` tone, `dot` icon, and an `sr_prefix` matching the nearest domain.
- Unknowns must also emit deterministic test/log evidence in the pure presenter tests so new domain states are intentionally added to the table instead of silently drifting.

## Redaction And Display Policy

Redaction is a shared rendering contract, not a per-page string convention.

Required behavior:

- All args, meta, callback payloads, callback errors, job errors, recorded output, and workflow result payloads render through the shared ArgsViewer/CodeBlock/RedactedValue path.
- `DisplayPolicy.render_job_field/3` tuple values map as follows: `{:raw_json, json}` renders as labelled JSON CodeBlock; `{:string, text}` renders as labelled string CodeBlock or text block according to caller context; `{:fallback, msg}` renders through RedactedValue.
- Enqueue-time field overlays use the exact visible copy `Redacted at enqueue`.
- Host policy redaction uses the exact visible copy `Hidden by display policy`.
- The fallback `[redacted]` remains acceptable only as the payload of RedactedValue, never as an unstyled literal in page markup.
- Redacted values are not copied, expanded, shown in tooltip/title, embedded in `data-*`, or reintroduced by JSON pretty printing.
- The shared component must preserve non-redacted sibling fields and must not mutate host-returned policy strings/maps.

Verification fixtures:

- Huge args map with nested redacted fields, long non-redacted IDs, arrays, non-ASCII text, and strings that look like HTML.
- Host policy returning string, map, nil/default, unavailable display, redacted display, and invalid/fallback paths.
- Stacktrace and long URL payloads from the forensics stress fixture.

Source: `.planning/REQUIREMENTS.md` DATA-04; `lib/oban_powertools/runtime_config.ex`; `test/support/showcase_catalog.ex`; `guides/brand-book.md` D-14 and D-19.

## Interaction And Accessibility

Required behavior for Phase 77:

- Semantic HTML first: native table, `dl`, ordered list timeline, `progressbar`, `pre`/`code`, `button`, and `a`. Do not use ARIA grid/menu roles for ordinary data tables.
- Sortable table headers are keyboard reachable buttons. Active sorted column sets `aria-sort="ascending"` or `aria-sort="descending"` on the header cell and exposes visible sort direction text or icon.
- DataTable loading uses `aria-busy="true"` on the owning region plus a named loading status. Empty/unavailable/permission-denied states remain perceivable and are not silently hidden.
- Error states that appear after an operator action or failed refresh use recovery copy and appropriate alert/status semantics.
- Row selection checkboxes have accessible names such as `Select job {id}` and remain 44px reachable at 320px.
- Pagination buttons are buttons or links matching behavior. Disabled pagination is perceivable and explains boundary state without relying on color.
- Stacked 320px table rows preserve column labels and row identity. No page-level horizontal scroll is allowed.
- Code/args blocks are the only Phase 77 components allowed to scroll internally; they must be keyboard scrollable and visibly bounded.
- Tooltips supplement truncated machine values but are not the only way to access full values. Provide a copy affordance or expanded view for full IDs when needed.
- Toast/Flash must not steal focus. Dismiss controls are keyboard reachable and visibly focusable. Error/danger messages remain readable after reduced motion disables transitions.
- Axe alone is insufficient. Targeted browser checks must prove sorting semantics, focus visibility, stacked table behavior, long value handling, redaction safety, toast roles, and 320px overflow.

Not proven here:

- FilterBar, DetailDrawer/Panel, ConfirmActionDialog, focus-trapped dialogs, page-level migration, full page keyboard traversal, final manual screen-reader review, and final 200% zoom/reflow closure remain Phase 78 or Phase 82 work.

Source: `.planning/REQUIREMENTS.md` A11Y-02..04 and DATA-03; Phase 73/74/75/76 verification patterns.

## Motion

| Motion Token | Contract |
|--------------|----------|
| `--obpt-motion-duration-fast` | Hover/focus/selected-row feedback, sort indicator feedback, toast close feedback. |
| `--obpt-motion-duration-base` | Toast/Flash appear/dismiss only when content is immediately readable and reduced-motion-safe. |
| `--obpt-motion-duration-slow` | Avoid in Phase 77 data components except inherited skeleton pulse. |
| `--obpt-motion-ease-standard` | Default data-display transition easing. |

Rules:

- Motion is feedback only. No ambient table, metric, timeline, or progress animation.
- Do not animate row insertion, sort reordering, progress width, toast layout, or error text in a way that delays reading or moves focus targets.
- Indeterminate long-running work uses named Spinner/Skeleton from primitives; ProgressBar is determinate unless it explicitly renders `Progress unavailable`.
- `prefers-reduced-motion` and `data-obpt-motion="reduce"` collapse non-essential transitions through existing tokens without hiding skeletons, status, focus, or toast content.

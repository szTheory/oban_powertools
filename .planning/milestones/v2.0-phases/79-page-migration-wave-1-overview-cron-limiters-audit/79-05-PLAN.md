## Must Haves — Decision Coverage

- **D-26:** Use DataTable plus the URL-owned adaptive detail and an explicit resource-specific Review blockers control while preserving read-only behavior, destinations, authorization, and inputs.
- **D-27:** Lock detail order to support truth, Current blockers, block-start snapshot, retained history/completeness, then runbook/Forensics/Oban Web destinations.
- **D-28:** Feed WhyBlocked normalized current evidence with scope, clearing condition, source, observation, and completeness; only complete empty current evidence is Runnable.
- **D-29:** Keep block-start snapshot and retained history separate from live state, time-labelled, and free of unsupported current/root-cause claims.
- **D-30:** Keep bridge/runbook destinations secondary and ownership-honest, gate Forensics server-side, and add no limiter mutation, polling, or combined timeline.

## Artifacts this phase produces

- New public Phoenix function component `ObanPowertools.Web.LimitersLive.page_content/1`, shared by `render/1` and later deterministic page stories; it performs no query, authorization, mutation, current-time lookup, or URL parsing.
- New semantic IDs: `limiters-page`, `limiters-table`, `limiter-{safe-id}`, `limiter-detail`, `limiter-current-blockers`, `limiter-block-start-snapshot`, `limiter-retained-history`, and `limiter-destinations`.
- New parent assigns: normalized `resource_rows`, `detail_state`, and `detail_presentation`; existing `selected_resource`, `history_summary`, `oban_dashboard_path`, and `read_only?` remain server-owned.
- Existing `inspect` event becomes resource-specific selection only; new `close_detail` event removes `resource` by replace patch. No mutation event is added.
- Canonical URL order uses existing `Selectors.limiter_path(resource: name)` and `Selectors.forensic_path(resource_type: "limiter", resource_id: name)`.
- Current blocker maps use the Phase 79 presenter fields including optional `affected_scope`; snapshot and retained-history presentation maps remain separate and are never passed as current blockers.
- Evidence state remains closed to the shipped `:current | :stale | :unavailable | :permission_denied`, with completeness `:complete | :partial | :unknown | :unavailable`; no new time-based stale threshold is invented.
- No limiter mutation, polling, combined timeline, provider adapter, route, authorization policy, stateful LiveComponent, packaged JavaScript, or dependency is added.

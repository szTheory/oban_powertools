## Design System

| Property | Value |
|----------|-------|
| Tool | Local Oban Powertools design system: `.obpt-root`-scoped semantic CSS custom properties in `assets/oban_powertools/tokens.css`; shadcn is not applicable. |
| Preset | Not applicable. This is an Elixir/Phoenix LiveView project with no `components.json`, Tailwind config, React, Next.js, Vite, or shadcn registry. |
| Component library | Reuse the shipped stateless `Phoenix.Component` modules `AppShell`, `Primitives`, `Forms`, `DataDisplay`, and `OperatorPatterns`. Parent LiveViews remain the stateful orchestration boundary. Do not add page-local substitutes, stateful LiveComponents, or a new UI runtime. |

## Spacing Scale

Phase 79 uses the existing 4, 8, 16, 24, 32, and 48px token subset. HEEx and page CSS must not introduce raw spacing values when a shipped token exists.

| Token | Value | Usage |
|-------|-------|-------|
| `--obpt-space-1` | 4px | Icon/text micro-gaps, status markers, compact metadata, separator offsets. |
| `--obpt-space-2` | 8px | Dense row internals, inline links/actions, compact zero states, label/value gaps. |
| `--obpt-space-4` | 16px | Narrow page gutter, narrow overlay body padding, stacked actions, ordinary section internals. |
| `--obpt-space-5` | 24px | Page-section separation, default surface padding, explanation-to-action rhythm. |
| `--obpt-space-6` | 32px | Wide page gutter, master/detail gutter, major section separation. |
| `--obpt-space-7` | 48px | Major showcase separation and hit-area derivation; avoid inside dense tables and evidence rows. |

Exceptions:

- Every actionable control exposes at least a 44px effective target, including row actions, pagination, filter removal, detail close, confirmation dismiss, and confirmation submit. Derive this through token-backed min-size/padding rules.
- DataTable rows retain the shipped 32–36px wide/tablet visual density while controls inside them retain 44px targets.
- The 320px viewport, 200% zoom, and the adaptive-detail breakpoint around `64rem` are responsive constraints, not spacing tokens.
- Focus uses the shipped 2px outline/offset and `--obpt-color-focus`. Do not introduce page-specific focus geometry.
- Only bounded code/evidence blocks may scroll horizontally. All other flex/grid children use `min-width: 0`, wrapping, or visibly signaled truncation.

Source: `guides/brand-book.md` D-15; `79-CONTEXT.md` D-07, D-43; shipped Phase 76–78 spacing contracts.

## Typography

Page-owned Phase 79 typography uses exactly four sizes and two weights. Shipped components retain their already-approved internal typography.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Dense table metadata / secondary evidence | 13px (`--obpt-font-size-sm`) | 400 (`--obpt-font-weight-regular`) | 1.4286 (`--obpt-line-height-base`) |
| Body / table value / control | 14px (`--obpt-font-size-md`) | 400 (`--obpt-font-weight-regular`) | 1.4286 (`--obpt-line-height-base`) |
| Section / component heading | 18px (`--obpt-font-size-xl`) | 600 (`--obpt-font-weight-semibold`) | 1.25 (`--obpt-line-height-tight`) |
| Page H1 | 28px (add/use `--obpt-font-size-page-title`, traced to brand D-15) | 600 (`--obpt-font-weight-semibold`) | 1.25 (`--obpt-line-height-tight`) |

Rules:

- Do not use weights 300, 500, 700, or heavier on these pages.
- Each page has exactly one 28px H1. Section headings are 18px; component-internal titles continue to use their shipped contracts.
- Counts, timestamps, page totals, and schedule numerals use sans plus `font-variant-numeric: var(--obpt-numeric-tabular)`.
- Mono is a scoped signal for cron expressions, IDs, hashes, module names, technical codes, and bounded evidence. Actor names, reasons, state labels, and ordinary counts remain sans.
- Introductory prose, reasons, recovery copy, and immutable audit sentences use sans and a bounded reading measure.
- Long English, Unicode, bidirectional text, and unbroken machine values must wrap or truncate visibly without reducing type below 13px.

Source: `guides/brand-book.md` D-13..D-15; `79-CONTEXT.md` D-04, D-06, D-07; shipped Phase 77–78 typography contracts.

## Color

All values resolve through semantic `--obpt-color-*` roles. Raw hex remains confined to the primitive palette in the token layer.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--obpt-color-surface`, `--obpt-color-text` | Page background, primary prose, table body, explanation and evidence content. |
| Secondary (30%) | `--obpt-color-elevated`, `--obpt-color-overlay`, `--obpt-color-border`, `--obpt-color-border-strong`, `--obpt-color-muted`, `--obpt-color-subtle` | Table headers, neutral handoffs, retention/history regions, detail/confirmation shells, separators, metadata. |
| Accent (10%) | `--obpt-color-accent-solid`, `--obpt-color-accent-bg`, `--obpt-color-accent-border`, `--obpt-color-accent-fg`, `--obpt-color-focus` | Safe primary links/actions, selected detail trigger, applied filter/selection state, pagination current state, and keyboard focus. |
| Destructive / danger | `--obpt-color-danger-solid`, `--obpt-color-danger-bg`, `--obpt-color-danger-border`, `--obpt-color-danger-fg` | Actual failed/error/permission-denied or danger status only. Phase 79 introduces no destructive action; Pause, Resume, and Run now all use warning intent. |

Accent reserved for: explicit safe navigation, selected Cron/Limiter/Audit evidence trigger, `Apply filters`, current pagination, safe fresh-preview recovery, Audit/Forensics destinations, and focus-visible treatment. Accent is not used for broad page chrome, every link, domain status, bridge ownership, resolved history, decorative fills, warning, success, or danger.

Semantic rules:

- Neutral chrome dominates every page. No gradients, alarm-card wall, badge soup, nested cards, or broad status fills.
- Status, ownership, severity, evidence completeness, and current-versus-historical meaning remain independent visible dimensions.
- Overview attention may use a restrained semantic marker only when the evidence supports it. Bridge-only and resolved-continuity surfaces remain neutral.
- Cron actions use warning tokens because they are consequential but not irreversible delete/cancel operations.
- Audit outcome does not color the global row as current truth. The selected entry may show a shared outcome pill only for a recorded outcome.
- Color is always paired with visible text plus icon, shape, border position, weight, or programmatic state.

## Cross-Page Information Hierarchy

Every page renders inside the existing `ThemeShell -> AppShell -> main#obpt-main` path. Do not instantiate another shell.

Shared page order:

1. One H1 and one plain-language introductory sentence.
2. Current support/permission truth when it materially changes what the operator can review or do.
3. The page's primary scan or triage surface.
4. One selected detail or one current explanation.
5. The legal next action nearest its explanation.
6. Evidence freshness/completeness.
7. Technical or immutable historical evidence.

Shared layout rules:

- Use one semantic DOM tree per page/component at every viewport. CSS and the shipped adaptive controller change geometry; never duplicate tables, details, controls, or sensitive content for mobile.
- One local decision has one visually primary action. Secondary Oban Web, Forensics, Audit, runbook, and close paths use neutral/link treatment.
- Do not put equal-weight actions above explanation. Do not make whole rows clickable.
- Avoid nested cards. A page section may own one shared Surface/Card with internal semantic sections and dividers.
- Page presenters receive schemas/domain structs, apply `DisplayPolicy` and finite allowlists, then pass normalized maps/scalars to components. Raw schemas and metadata never enter shared components.
- Repository work, authorization, URL parsing, mutations, and receipts stay outside `render/1` and outside shared components.

Source: `79-CONTEXT.md` D-01..D-08; `79-RESEARCH.md` Recommended Cross-Page Architecture.

## Copywriting Contract

The phase voice is calm, precise, consequence-first, and ownership-honest. Centralized presenter helpers supply complete copy; templates do not fabricate sentences from raw atoms, metadata, exceptions, or query syntax.

### Page headers and primary actions

| Page | H1 | Introductory copy | Primary action contract |
|------|----|-------------------|-------------------------|
| Overview | `Overview` | `See what needs attention, why it matters, and where to continue.` | No global CTA. Each ordered lane has at most one verb+noun next step; bridge uses `Inspect in Oban Web`. |
| Cron | `Cron` | `Review schedules, inspect one cron entry, and take deliberate action with recorded evidence.` | Selected detail only: `Pause cron entry` or `Resume cron entry`, plus `Run cron entry now`. |
| Limiters | `Limiters` | `Review limiter state, understand what blocks progress now, and follow the right evidence path.` | Row/detail action: `Review blockers`; accessible name `Review blockers for {limiter}`. |
| Audit | `Audit` | `Review recorded operator actions and the evidence available for each record.` | Row action: `View evidence`; accessible name `View evidence for {human event} on {target}`. |

### Empty and error copy

| Page / state | Heading | Body / recovery |
|--------------|---------|-----------------|
| Overview all quiet | `No current follow-up identified` | `Available evidence identifies no current native or bridge follow-up. Open Jobs to review individual job state.` |
| Overview lane zero | `No {lane noun} identified` | One truthful fact plus the lane's existing destination. Never imply monitoring completeness. |
| Cron empty | `No cron entries available` | `No cron entries are configured for this host. Check the host cron configuration.` |
| Cron error | `Cron entries did not load` | `Refresh the page. If the problem continues, check the host logs.` |
| Limiters empty | `No limiters configured` | `This host has no limiter resources to review. Open Jobs to review current work.` |
| Limiters error | `Limiter state did not load` | `Refresh the page. If the problem continues, check the host logs.` |
| Audit empty, unfiltered | `No audit records recorded` | `Recorded operator actions will appear here when evidence is available.` |
| Audit empty, filtered | `No audit records match these filters` | `Remove a filter or clear all filters to widen the review.` |
| Audit error | `Audit records did not load` | `Retry the request. If the problem continues, check the host logs.` |

### Required terminology and absence copy

| Context | Exact copy |
|---------|------------|
| Overview primary region | `Current attention` |
| Overview ordered lanes | `Needs Review`, `Blocked`, `Waiting`, `Bridge-only Follow-up`, `Runnable`, `Resolved continuity` |
| Bridge sample count | `{N} representative follow-ups` or `{N} shown` |
| Bridge ownership action | `Inspect in Oban Web` |
| Limiter current section | `Current blockers` |
| Limiter complete empty current evidence | `Runnable` |
| Limiter historical sections | `Snapshot at block start`; `Retained history` |
| Audit retention region | `Repair evidence retention` |
| Audit absolute time label | `Recorded at` |
| Audit missing reason | `No operator reason recorded` |
| Audit missing outcome | `Outcome not recorded` |
| Audit missing source | `Source not recorded` |
| Audit missing correlation | `Correlation not recorded` |
| Reason label and hint | `Reason`; `Explain why this action is needed. Do not enter secrets.` |
| Blank reason error | `Enter a reason before continuing.` |

Copy prohibitions:

- Never render `Are you sure?`, bare `Confirm`, ambiguous `Cancel`, `Something went wrong`, `An error occurred`, `N/A`, `root cause` without proof, or raw `inspect(error)` output.
- Never expose preview tokens, plan hashes, action atoms, raw event/query syntax, source table names, ranks, Ecto structs, exceptions, stacktraces, or provider-shaped metadata.
- Do not say `recently` for resolved continuity, `global total` for the bridge sample, `No blockers` from incomplete evidence, or that a run-now job `ran` without authoritative evidence.

## Overview Page Contract

The Overview is a stable triage page, not a configurable dashboard.

| Region | Visual Contract | Interaction / Truth Contract |
|--------|-----------------|------------------------------|
| Header | H1 `Overview` and the exact intro above. No summary hero, diagnosis boilerplate, or live-region chrome. | Static Overview state has no `role="alert"` or live region. |
| Current attention | One H2 followed by `Needs Review -> Blocked -> Waiting` in this DOM order. Wide may use two columns; narrow is one column without reordering. | Preserve `AttentionProjection` ranking and at most three exemplars per lane. Counts, source facts, selectors, and authorization remain unchanged. |
| Nonzero current lane | Use `attention_card/1` only when title, summary, impact, observation time, status, severity, and completeness are honest. Supporting exemplars are direct separated list rows, not nested cards. | Each exemplar has an explicit selector/destination link. The card is persistent, not dismissible, and not live by default. |
| Zero current lane | Compact neutral bucket-specific fact plus the existing relevant route. Do not render a large empty card for every zero. | Zero means no identified item in available evidence, not complete monitoring. |
| Bridge-only Follow-up | Full-width neutral handoff immediately after current attention. Show representative-sample wording and explicit Oban Web ownership. | Action is `Inspect in Oban Web`. Never style it as a native mutation or comparable total metric. |
| Runnable | Compact `metric_card/1` or status summary after the bridge. | Current capacity context, not an attention alarm and not proof of future completion. |
| Resolved continuity | Final calm neutral evidence region; no green success card. | Historical continuity only. Do not claim a recent-time window or current state. |

The lane order is immutable across count, timestamp, theme, client state, viewport, and severity. Do not add charts, polling, configurable cards, feeds, or duplicated mobile markup.

## Cron Page Contract

Cron is selection-first control: scan schedules, select one entry, understand context, then act deliberately.

| Region / state | Visual Contract | Interaction / Truth Contract |
|----------------|-----------------|------------------------------|
| Scan table | `data_table/1` with caption `Cron entries` and columns Entry, Schedule, Policies/support, and State. Entry name is an explicit patch link. No Actions column, row buttons, kebab menu, or whole-row click. | Existing `?entry=` identity remains canonical. Table state is explicit: loading, empty, ready, unavailable, permission denied, or error. |
| Selected detail | Existing `detail_surface/1`. Order: entry name/current state and support truth; schedule/policies; relevant history/evidence; visible actions. | Detail is the only mutation venue. Direct and reloaded URLs resolve the same selection. Invalid/missing selection fails safely. |
| Action availability | `Pause cron entry` or `Resume cron entry`, then `Run cron entry now`. At 320px actions stack full-width. | Unauthorized actions may remain discoverable, disabled with a plain server-derived reason. Disabled state is never authorization. |
| Confirmation transition | Render one `confirm_action_dialog/1` and stop rendering the adaptive detail while confirmation is active. Retain selected entry and `?entry=`. | Never nest modal detail and confirmation. Parent checks authorization before preview and again before execution with the current principal. |
| Recoverable result | Expired, drifted, consumed, skipped, partial, or failed result stays open with specific recovery and `Create new preview`. Preserve only the safe reason draft. | Never silently refresh and execute. Focus moves to the labelled result/recovery heading. |
| Clean success | Confirmation leaves the DOM; repository truth reloads; one exact Toast/Flash receipt appears with an Audit destination. | Restore focus to updated detail action or logical row/name fallback. Do not emit a duplicate generic flash/banner. |

### Confirmation copy

| Action | Confirm label | Dismiss label | Consequence and non-effect |
|--------|---------------|---------------|----------------------------|
| Pause | `Pause cron entry` | `Keep running` | `Future schedule claims stop. Work that is already running or enqueued is unaffected.` |
| Resume | `Resume cron entry` | `Keep paused` | `Future schedule claims continue. Missed work is not run retroactively.` |
| Run now | `Run cron entry now` | `Keep current schedule` | `Powertools attempts a manual schedule-slot claim. Overlap policy may skip, queue, or enqueue it.` |

All three use warning intent and a trimmed nonblank reason. The dialog starts focus on the labelled consequence, contains focus, closes with Escape only while dismissible, and uses normal LiveView loading/disabled semantics to suppress accidental duplicate activation. Durable preview identity, expiry, drift, single-use checks, plan hash, overlap policy, transaction, and audit write remain server authority and are never displayed.

Receipt patterns:

- Pause: `Cron entry {name} paused. Audit evidence recorded.` only when both facts are authoritative.
- Resume: `Cron entry {name} resumed. Audit evidence recorded.` only when both facts are authoritative.
- Run now: `Manual slot claim recorded for {name}: {recorded result}. Audit evidence recorded.` Never say the job ran unless an authoritative result proves completion.

|--------|-----------------|------------------------------|
| Scan table | `data_table/1` with caption `Limiters` and columns Limiter, Scope, State, and one explicit action. | Row action is `Review blockers` with resource-specific accessible name. Preserve `?resource=`; no whole-row click or mutation controls. |

## Audit Page Contract

Audit is a bounded scan index plus one immutable evidence detail. It is not a causal timeline.

| Region | Visual Contract | Interaction / Truth Contract |
|--------|-----------------|------------------------------|
| Read-only/support truth | Neutral information near the header; no amber alarm or urgency role. | No mutation, selection checkbox, bulk action, action menu, auto-refresh, or live tail. |
| Repair evidence retention | Restrained neutral `Repair evidence retention` region above results. Distinguish archived repair evidence from live Audit rows. | State only what the ledger proves. Do not claim a retention guarantee for the whole Audit table or that archived repairs appear in the table. |
| Filters | Shipped `filter_bar/1` in submit mode for exact `resource_type`, `resource_id`, and `event_type` meanings. Applied filters use human labels, individual remove, and `Clear filters`. | Applying/removing/clearing resets page to 1 and removes selection while retaining remaining scope. Do not add actor, free text, dates, saved views, export, facets, query grammar, or filter-from-detail. |
| Scan table | Compact `data_table/1` with caption `Audit records` and columns Event, Target, Actor, Reason, Recorded at, and one evidence action. Rows are not clickable. Job target links remain independent. | Stable 20-row pages ordered `inserted_at DESC, id DESC`. Exact result/page summary and Previous/Next URLs make every match reachable. |
| Selected detail | One `audit_entry/1` inside `detail_surface/1`. The heading is an immutable past-tense sentence; fields are actor, action, target, complete safe reason, source, recorded outcome, Recorded at, and genuine correlation/evidence. | `event=<audit-row-id>` composes with filters/page. Selection must match active filter scope. Missing/malformed/mismatched IDs render safely without leaking existence. |
| Evidence | Only allowlisted scalar recorded facts with consumer labels; technical evidence is progressively disclosed only when safe. | Never pass `event.metadata` wholesale. No secret originals, preview tokens, plan hashes, command keys-as-correlation, credentials, raw exceptions, stacktraces, or provider blobs in visible or hidden DOM. |

URL behavior:

- First evidence selection pushes history; switching evidence replaces the selected URL.
- Closing detail removes only `event` and preserves filters/page.
- Previous/Next preserves filters and removes or safely re-resolves selection.
- Absolute UTC `Recorded at` is primary. Relative time may supplement but never replace it.
- `command_key` and row ID are identities, not correlation. Event suffixes do not prove outcome. A later result remains a separate immutable record.

## Interaction and Accessibility

- Use semantic HTML first: headings/sections, native table/caption/header cells, links, buttons, forms/labels/errors, description lists, time, article, and native dialog. Do not add ARIA grid, menu, or row-click semantics.
- Each page has one H1 and a logical heading/landmark order. Scan tables have meaningful captions and preserve one table tree at every viewport.
- Entry/resource/evidence controls have resource-specific accessible names. Job target links remain separate from evidence actions.
- Every interactive element is keyboard reachable/operable with visible, unobscured focus in system, light, dark, and high-contrast themes.
- Row actions, filter removal, pagination, close, and confirmation controls meet the 44px effective target.
- Selection has programmatic and visible state (`aria-expanded` / `aria-controls` plus restrained accent/weight). Color alone never carries selection, status, severity, completeness, permission, or outcome.
- Confirmation and narrow detail use native modality/focus containment. Wide detail never traps focus or makes the background inert. At most one dialog is active and at most one modal is open.
- Resize with an open detail preserves one DOM identity, selection, readable content, and logical focus. Opening Cron confirmation removes/leaves detail before the modal opens.
- Reduced motion never hides content or delays action/focus. Keyboard operation is not animated.
- Screen-reader announcements are exact and sparse: applied filter result summary, useful selected-detail completion, confirmation result/recovery focus, and one clean success receipt.
- Axe must report zero critical/serious issues, but connected browser proof must also cover focus order, Tab containment, Escape, restore, Back/direct URLs, 320px reflow, 200% zoom, reduced motion, table navigation, and confidential DOM absence.

## Security, Privacy, and Authority Presentation

- Parent LiveViews authorize page/resource/action access server-side. Disabled controls and hidden CSS are never authority.
- Cron authorizes before preview and immediately before execution with the current principal; durable drift, expiry, single use, transaction, and audit checks remain authoritative.
- Normalize and structurally allowlist presentation data before component rendering. Shared components receive only plain safe maps/scalars.
- Secret originals, preview tokens, plan hashes, credentials, principal maps, raw metadata, raw exceptions, stacktraces, and configuration/provider blobs must be absent from text, attributes, titles, hidden nodes, URLs, serialized showcase fixture payloads, logs, telemetry, and copy buffers.

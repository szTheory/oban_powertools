# Phase 73 - UI Design Contract

> Visual and interaction contract for the Visual-Regression & A11y Harness phase. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none; shadcn is not applicable because this project is Phoenix/LiveView with a repo-owned token layer, not React/Next/Vite. Source: codebase scan, RESEARCH.md |
| Preset | not applicable |
| Component library | Phoenix.Component / Phoenix.LiveView plus the existing `.obpt-root` scoped CSS token system. No third-party UI component library enters this phase. |
| Icon library | none introduced in Phase 73. Harness output must rely on text labels, status names, and existing semantic color tokens; future component icons are owned by later phases. |
| Font | `--obpt-font-sans` for prose and controls; `--obpt-font-mono` only for literal machine values such as story IDs, selectors, snapshot paths, and command names. Source: `guides/brand-book.md` D-13/D-14 and `assets/oban_powertools/tokens.css` |

Design posture: Phase 73 is guardrail infrastructure. It must preserve and verify the existing Powertools identity rather than redesigning the showcase, adding components, or creating decorative report UI. The visible surface under test is the Phase 72 `/ops/jobs/_showcase` route inside `.obpt-root`.

Primary focal point and hierarchy: each captured catalog story cell is the visual anchor. Within and around that anchor, severity/status labels are the second-level signal, followed by supporting metadata such as story IDs, domains, personas, selectors, snapshot names, and finally controls for theme, viewport, report filtering, or baseline review.

## Spacing Scale

Declared values (must use only 4px, 8px, 16px, 24px, 32px, 48px, or 64px):

| Token | Value | Usage |
|-------|-------|-------|
| `--obpt-space-1` | 4px | Icon/text gaps, inline metadata gaps, compact badge spacing |
| `--obpt-space-2` | 8px | Compact control gaps, button vertical padding, segmented-control gaps |
| `--obpt-space-3` | 8px | Dense row internals, card/header micro-gaps, compact input horizontal padding |
| `--obpt-space-4` | 16px | Default element spacing, control groups, section padding |
| `--obpt-space-5` | 24px | Major panel padding, story-grid gaps, modal padding |
| `--obpt-space-6` | 32px | Showcase page padding and larger layout separation |
| `--obpt-space-7` | 48px | Largest phase-level section breaks; do not invent 64px spacing in this phase |

Exceptions: Browser viewport dimensions are fixed by the test matrix, not design spacing: `320x900`, `768x1000`, and `1440x1000`. Screenshot output dimensions and PNG paths are test artifacts, not UI spacing tokens. Touch/click targets must remain at least 44px where this phase touches interactive controls; existing controls must not be compressed to satisfy screenshot density.

## Typography

Use exactly these four phase roles. Do not add new font sizes or weights in the harness UI, docs snippets, or generated report wrappers.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px (`--obpt-font-size-md`) | regular 400 (`--obpt-font-weight-regular`) | 1.4286 (`--obpt-line-height-base`) |
| Label | 13px (`--obpt-font-size-sm`) | semibold 600 (`--obpt-font-weight-semibold`) | 1.25 (`--obpt-line-height-tight`) |
| Heading | 16px (`--obpt-font-size-lg`) | semibold 600 (`--obpt-font-weight-semibold`) | 1.25 (`--obpt-line-height-tight`) |
| Display | 18px (`--obpt-font-size-xl`) | semibold 600 (`--obpt-font-weight-semibold`) | 1.25 (`--obpt-line-height-tight`) |

Machine-readable values such as `showcase/jobs-long-identifiers-many`, `[data-obpt-story="..."]`, `ci-gate`, `visual_a11y`, `npm run visual:a11y`, and `--update-snapshots=changed` must use monospace only when rendered as code or command text. Numeric counts in prose stay sans with tabular numerals where styled.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--obpt-color-surface` (`#ffffff` light, `#0e1116` dark, `#020617` high-contrast) | Showcase background, story-cell backgrounds, report wrappers owned by this repo |
| Secondary (30%) | `--obpt-color-elevated`, `--obpt-color-border`, `--obpt-color-muted` | Cards, control panels, fixture-index rows, inactive segmented controls, structural separators |
| Accent (10%) | `--obpt-color-accent-*` indigo role tokens | Safe primary actions, selected showcase viewport/theme controls, active tabs, and intentional current-selection affordances only |
| Destructive | `--obpt-color-danger-*` red role tokens | Destructive/error states only: serious/critical axe failures, failed CI lane summaries, and baseline-update warnings when they indicate regression risk |

Accent reserved for: selected controls, safe primary actions, active navigation/tabs, and focus-related affordances through `--obpt-color-focus`. Accent must not be used for status pills, warnings, danger states, decorative fills, snapshot diff highlights, or arbitrary report chrome. `info` uses cyan, `warning` uses amber, `success` uses emerald, and `danger` uses red; these roles must remain visually and semantically distinct in every captured theme.

Phase 73 visual assertions must preserve the brand-book rule that color is information, never decoration, and never the sole signal. Screenshot masks or styles must not hide status colors, focus outlines, long identifiers, RTL/non-ASCII content, redaction displays, warning/danger cues, or severity labels.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | Run visual and accessibility gate |
| Empty state heading | No visual diffs found |
| Empty state body | Snapshots match the committed baselines. Review the axe artifact for non-blocking findings before merging. |
| Error state | Visual or accessibility gate failed. Review the Playwright report, diff images, and axe JSON artifact, then fix the UI or update the affected baselines in Docker with a PR explanation. |
| Destructive confirmation | No product destructive action is introduced. Baseline update process copy: `Update snapshots only when the visual change is intentional; explain the reason in the PR.` |

Copy rules:

- Use "visual and accessibility gate" for the combined CI lane and "visual diff" for screenshot mismatch output.
- Use "critical" and "serious" for merge-blocking axe findings; keep "moderate", "minor", and "incomplete" visible in artifacts without calling them passing work.
- Never claim "WCAG 2.2 AA verified" from axe alone. Use: "Automated axe gate passed for critical and serious findings on the captured showcase targets."
- Baseline-update docs must use consequence-first copy: updating a snapshot changes the expected UI contract and requires review.

## Phase 73 Interaction Contract

### Capture Surface

The browser harness must drive the real dev/test-only showcase route from `examples/phoenix_host`:

- Route: `/ops/jobs/_showcase`
- Root: exactly one `.obpt-root`
- Theme attributes: `data-obpt-theme`, `data-obpt-effective-theme`, `data-obpt-motion`
- Theme controls: `[data-obpt-theme-choice="system|light|dark|high-contrast"]`
- Viewport controls: `[data-obpt-viewport="320|tablet|wide"]`
- Story targets: `[data-obpt-story="{scenario-id}"]`
- Structural sections: `[data-obpt-section]`

Do not snapshot placeholder sections for future phases. In Phase 73, screenshots are limited to catalog-backed story cells from `ObanPowertools.ShowcaseCatalog.scenarios/0`.

### Required Matrix

| Axis | Values | Contract |
|------|--------|----------|
| Stories | `overview-operational-empty`, `jobs-long-identifiers-many`, `batches-high-count-mixed-severity`, `workflows-stale-disconnected-dag`, `cron-permission-denied`, `limiters-boundary-pagination`, `lifeline-repair-preview`, `audit-non-ascii-rtl`, `forensics-long-url-stacktrace` | Generated from `test/support/showcase_catalog.ex`; never duplicated by hand in TypeScript |
| Themes | `system`, `light`, `dark`, `high-contrast` | Set through `window.ObanPowertoolsTheme.setTheme(theme)` or the stable theme controls; `system` must be deterministic through Playwright media emulation |
| Viewports | `320`, `tablet`, `wide` | Set real browser viewport first, then mirror the showcase viewport control |
| Browser | Chromium in the pinned Playwright Docker image | No host-browser baselines |

Expected Phase 73 baseline count: 9 stories x 4 themes x 3 viewports x 1 browser = 108 committed PNGs.

### Visual Behavior

- Use story-level `toHaveScreenshot` assertions, not full-page screenshots.
- The story cell remains the primary visual anchor in every capture; severity/status labels rank next; supporting metadata and controls must stay subordinate and must not visually compete with the story content.
- Baseline paths must be human-readable and grouped by project, story, theme, and viewport.
- Wait for route readiness, one `.obpt-root`, selected theme/effective theme, selected viewport, target story visibility, network idle where useful, and `document.fonts.ready` before capture.
- Disable animations, hide caret, fix timezone/locale/media preferences, and set `reducedMotion: "reduce"` for deterministic capture.
- Mask only genuinely volatile pixels. Do not mask fixture content, selectors, state labels, status tones, focus states, redaction displays, long machine values, RTL/non-ASCII/emoji text, or severity signals.

### Accessibility Behavior

- Axe scans run against the same story selectors and matrix as VRT.
- WCAG A/AA tags including supported WCAG 2.2 AA rules are enabled according to the installed axe-core version.
- Merge-blocking threshold: zero `critical` or `serious` violations.
- Full axe JSON, including `moderate`, `minor`, `incomplete`, `passes`, and `inapplicable`, must be uploaded as review artifacts.
- Reserved open-state metadata such as `confirm_action_open`, `tooltip_open`, and `drawer_open` becomes a scan target only when real open-state DOM exists in later phases.

### Baseline Review Workflow

- CI never updates snapshots.
- Local snapshot updates run only in the pinned Playwright Docker environment.
- Default update mode is the narrowest practical command, `--update-snapshots=changed`.
- A PR that changes `test/browser/__screenshots__/**/*.png` must explain why the visual contract changed.
- Failed visual/a11y runs must publish short-retention artifacts containing Playwright HTML output, actual/expected/diff images, axe JSON, and the generated manifest.

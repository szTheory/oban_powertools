## Spacing Scale

Shell CSS and components must use existing Powertools spacing tokens or token-backed classes. Do not introduce raw component spacing values in HEEx source.

| Token | Value | Usage |
|-------|-------|-------|
| `--obpt-space-1` | 4px | Active-route indicator offset, icon/text micro-gaps if an internal glyph is used, tight breadcrumb separators. |
| `--obpt-space-2` | 8px | Nav link internal gaps, compact nav link horizontal padding, theme-control gaps, breadcrumb item gaps, compact header item spacing. |
| `--obpt-space-4` | 16px | Header control padding, default nav link horizontal padding, default shell padding, mobile nav stack gap, header row gap, main content inset at 320px. |
| `--obpt-space-5` | 24px | Header-to-main separation, breadcrumb-to-content separation, tablet shell padding. |
| `--obpt-space-6` | 32px | Wide viewport shell gutters and showcase story grouping. |
| `--obpt-space-7` | 48px | Major showcase spacing and minimum comfortable control target derivations; avoid as routine nav gap. |
| Phase maximum | 64px | Reserved for wide outer gutters only if needed; do not use inside header, nav, theme controls, or breadcrumbs. |

Exceptions:

- The mobile nav disclosure button, theme-choice buttons, and any icon-only fallback target must expose at least a 44px effective hit target through token-backed `min-height`/padding.
- The 320px viewport is a test target, not a spacing token. The shell must fit at 320px without page-level horizontal scroll.
- Focus geometry uses the existing 2px focus outline/offset and `--obpt-color-focus`; do not create shell-specific focus ring geometry.
- Use `min-width: 0`, wrapping, and bounded overflow rules anywhere a flex/grid child contains route labels, actor labels, or breadcrumbs.

Source: `guides/brand-book.md` D-15; `assets/oban_powertools/tokens.css`; `.planning/REQUIREMENTS.md` NAV-02 and A11Y-03.

## Typography

Use exactly these shell roles and only weights 400 and 600.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body / nav link | 14px (`--obpt-font-size-md`) | 400 (`--obpt-font-weight-regular`) | 1.4286 (`--obpt-line-height-base`) |
| Nav current / control label | 14px (`--obpt-font-size-md`) | 600 (`--obpt-font-weight-semibold`) | 1.4286 (`--obpt-line-height-base`) |
| Breadcrumb / actor metadata | 13px (`--obpt-font-size-sm`) | 400 (`--obpt-font-weight-regular`) | 1.25 (`--obpt-line-height-tight`) |
| Shell brand / story heading | 20px | 600 (`--obpt-font-weight-semibold`) | 1.25 (`--obpt-line-height-tight`) |

Rules:

- Do not introduce 300, 500, 700, or heavier weights in Phase 76 shell UI.
- Page headings inside existing LiveViews remain page-owned until Phases 79-81; Phase 76 shell typography must not restyle page-body headings globally.
- Nav labels and breadcrumbs use sentence/title case as listed in the copy contract; no all-caps navigation.
- Actor labels and breadcrumb segments must wrap or truncate visibly at 320px; do not shrink below 13px.
- Numeric counts, timestamps, IDs, and machine values remain page/body concerns, not shell typography.

Source: `guides/brand-book.md` D-13..D-15; `assets/oban_powertools/tokens.css`; Phase 74/75 UI-SPEC typography constraints.

## Color

Components reference semantic `--obpt-color-*` roles only. Raw hex remains confined to the token layer.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--obpt-color-surface`, `--obpt-color-text` | Root shell background, main content background, default header text, ordinary nav labels. |
| Secondary (30%) | `--obpt-color-elevated`, `--obpt-color-border`, `--obpt-color-muted`, `--obpt-color-subtle` | Header band, nav container, breadcrumb, actor/context label, separators, inactive theme controls. |
| Accent (10%) | `--obpt-color-accent-solid`, `--obpt-color-accent-bg`, `--obpt-color-accent-border`, `--obpt-color-accent-fg`, `--obpt-color-focus` | Current route, selected theme choice, safe navigation emphasis, and keyboard focus only. |
| Destructive | `--obpt-color-danger-solid`, `--obpt-color-danger-bg`, `--obpt-color-danger-border`, `--obpt-color-danger-fg` | Reserved for page-owned destructive/error UI. The Phase 76 shell must not render destructive actions. |

Accent reserved for: active/current route state, selected theme choice, focus-visible treatment, and safe link emphasis. Accent must not be used for broad header chrome, decorative backgrounds, every nav link, warning, success, danger, or status meaning.

State rules:

- Current nav item uses at least three signals: `aria-current="page"`, semibold text, and an accent-backed border/shape/background treatment. Color alone is insufficient.
- Breadcrumb current segment uses `aria-current="page"` and visible current-state text weight or separator treatment.
- Inactive nav links remain neutral; hover/focus may use accent border/focus tokens but must not look selected.
- Theme choices use the existing `data-obpt-theme-choice` mechanism. The selected choice uses `aria-pressed="true"` plus accent treatment; unselected choices remain neutral.
- High-contrast mode must preserve visible nav separation, focus, selected theme, and current route without component-local theme overrides.

Source: `guides/brand-book.md` D-05, D-07..D-12; `assets/oban_powertools/tokens.css`; `.planning/REQUIREMENTS.md` NAV-03 and A11Y-02.

## Copywriting Contract

Shell copy is product navigation and operator context, not marketing copy. Use sentence case except the route labels below, which are canonical nav labels.

| Element | Copy |
|---------|------|
| Primary CTA | `Open navigation` |
| Empty state heading | `No shell stories registered` |
| Empty state body | `Add token-backed shell stories before updating visual baselines.` |
| Error state | `Shell stories did not load. Regenerate the showcase manifest and check the shell story catalog.` |
| Destructive confirmation | None in Phase 76. The shell renders no destructive action. Confirmation flows remain Phase 78/page-owned work. |

Primary nav labels, in order:

| Surface | Path Pattern | Nav Label | Breadcrumb Label |
|---------|--------------|-----------|------------------|
| Engine overview | `/` | `Overview` | `Overview` |
| Jobs | `/jobs`, `/jobs/:id` | `Jobs` | `Jobs`; detail route fallback `Job detail` |
| Batches | `/batches`, `/batches/:id` | `Batches` | `Batches`; detail route fallback `Batch detail` |
| Workflows | `/workflows`, `/workflows/:id` | `Workflows` | `Workflows`; detail route fallback `Workflow detail` |
| Cron | `/cron` | `Cron` | `Cron` |
| Limiters | `/limiters` | `Limiters` | `Limiters` |
| Lifeline | `/lifeline` | `Lifeline` | `Lifeline` |
| Audit | `/audit` | `Audit` | `Audit` |
| Forensics | `/forensics` | `Forensics` | `Forensics` |

Copy rules:

- Primary nav contains exactly the 9 native Powertools surfaces above. Do not include the optional `/ops/jobs/oban` bridge in primary nav.
- If the optional Oban Web bridge is surfaced anywhere, it is secondary/contextual only and labeled `Oban Web bridge` with `Inspection only` support-truth copy.
- Shell brand text is `Oban Powertools`; do not use a marketing tagline in the header.
- Actor/context display uses available existing actor data only. Recommended label: `Actor: {principal}`. If no durable display value exists, render `Actor context unavailable`; do not invent tenant, cluster, environment, or account labels.
- Theme choices are `System`, `Light`, `Dark`, and `High contrast`.
- Breadcrumb root is `Overview`; the current crumb must be explicit. Detail routes may use page-provided labels later, but the Phase 76 fallback must be `Job detail`, `Batch detail`, or `Workflow detail`.
- Error copy names the recovery path. Do not use `Something went wrong`.

Source: `.planning/phases/76-navigation-app-shell/76-RESEARCH.md` nav-label recommendation and open questions; `lib/oban_powertools/web/router.ex`; `guides/brand-book.md` D-16..D-21.

## App Shell Component Contract

| Component Area | Visual Contract | Interaction / Accessibility Contract |
|----------------|-----------------|--------------------------------------|
| Shell root | New component owns `.obpt-app-shell` inside `.obpt-root`. It surrounds page body content without restyling page internals. | Render through `ThemeShell.live/1` around `@inner_content`. Parent LiveViews keep data, events, authorization, and page body behavior. |
| Skip link | First focusable element, visually revealed on focus, positioned before header/nav. | Link text is `Skip to main content`; target is `main#obpt-main`; main has `tabindex="-1"` so activation moves focus. |
| Header | Restrained elevated band with border-bottom, not a floating card. Header wraps into multiple rows at narrow widths. | Header order is brand, nav disclosure/control, primary nav, actor/context, theme choices. Non-interactive actor display must not enter tab order. |
| Primary nav | Native `<nav aria-label="Powertools surfaces">` with the 9 labels above. Wide/tablet layout is wrap-enabled horizontal; mobile layout is disclosure-controlled vertical. | Use links, not `menu`/`menubar` roles. Active item has `aria-current="page"`. Link order stays identical across viewports. |
| Mobile disclosure | Button label `Navigation`; neutral button treatment; visible current state when open. | Use `button[type="button"]` with `aria-expanded`, `aria-controls="obpt-primary-nav"`, and one scoped JS/data source of truth. Enter, Space, and click toggle. Collapsed links are not tabbable at 320px. Escape closes if focus is inside the disclosure region. |
| Breadcrumb | Native `<nav aria-label="Breadcrumb">` below/inside header, muted secondary treatment, wraps before overflow. | Use ordered list semantics or equivalent list markup. Final crumb has `aria-current="page"`. Breadcrumb is not the primary nav. |
| Theme controls | Four visible choices: System, Light, Dark, High contrast. Use tokenized segmented/wrap layout, not icon-only controls. | Reuse existing `data-obpt-theme-choice` and `window.ObanPowertoolsTheme` behavior. Each choice is a button with `aria-pressed` reflecting the current requested theme. Theme state stays on `.obpt-root`, never `<html>`. |
| Actor/context | Compact neutral metadata, right-aligned on wide and stacked/wrapped on mobile. | Text only. It must not imply authorization state and must not show mutation controls. Page/action authorization remains in `LiveAuth`. |
| Main content | `main#obpt-main` uses dominant surface, token-backed layout gutter, and `min-width: 0`. | Existing LiveViews render unchanged inside main. Phase 76 may integrate the wrapper but must not migrate page body markup or page-owned flows. |

API rules:

- Preferred module: `ObanPowertools.Web.Components.AppShell`.
- Use `attr/3`, `slot/3`, closed values, and explicit assigns for `current_path`, `current_uri`, `current_actor`, optional `actor_label`, optional `context_label`, `nav_items`, and `inner_block`.
- Nav labels and paths are server-controlled data from a central closed nav model. Do not accept caller-provided HTML labels.
- Filter or reject caller `class` and `style` escape hatches on shell components. Visual variants are component-owned and token-backed.
- Shell JS must stay in `assets/oban_powertools/theme.js` or a same-asset scoped module, use `.obpt-root` scoping, fixed data attributes, and no dynamic code evaluation.

Source: `.planning/phases/76-navigation-app-shell/76-RESEARCH.md` Architecture Patterns and Responsibility Map; `lib/oban_powertools/web/theme_shell.ex`; Phase 74/75 component API rules.

## Interaction And Accessibility

Required behavior for Phase 76:

- Semantic HTML first: `header`, `nav`, `main`, links, buttons, and list markup. Do not use ARIA menu roles for app navigation.
- Logical focus order: skip link -> header brand/disclosure -> nav links -> actor/context only if interactive in the future -> theme choices -> main content.
- Every interactive shell control is keyboard reachable, keyboard operable, and visibly focusable in system, light, dark, and high-contrast themes.
- The mobile disclosure updates `aria-expanded` and visible state together. At 320px, collapsed nav links must not remain in the tab sequence.
- Active-route state is programmatic and visual: `aria-current="page"` plus non-color visual treatment.
- Breadcrumb has `aria-label="Breadcrumb"` and a single current page segment.
- The shell must have no page-level horizontal scroll at 320px. Header, nav, theme controls, actor text, and breadcrumbs wrap or truncate visibly.
- No unusable nested scrolling: only page-owned bounded code/args blocks may scroll internally in later phases.
- Theme controls must not cause layout shift or FOUC. Existing `.obpt-root` `data-obpt-theme` and `data-obpt-effective-theme` remain the only theme state.
- Axe alone is insufficient. Targeted browser checks must prove skip-link focus transfer, disclosure keyboard behavior, active route/breadcrumb, theme state, focus order, and 320px overflow.

Not proven here:

- Page-body migration, final page-level keyboard traversal, dialog focus trap/restore, reduced-motion manual sweep, 200% zoom/reflow closure, and complete manual screen-reader announcement quality remain later phases.

Source: `.planning/REQUIREMENTS.md` NAV-02..04 and A11Y-02; `.planning/phases/76-navigation-app-shell/76-RESEARCH.md`; Phase 73/74/75 verification patterns.

## Motion

| Motion Token | Contract |
|--------------|----------|
| `--obpt-motion-duration-fast` | Hover/focus/current-route feedback and disclosure state feedback. |
| `--obpt-motion-duration-base` | Optional disclosure panel open/close feedback only if content remains immediately reachable and reduced-motion-safe. |
| `--obpt-motion-duration-slow` | Avoid in shell UI. |
| `--obpt-motion-ease-standard` | Default shell transition easing. |

Rules:

- Motion is feedback only. No ambient header, nav, or theme-control animation.
- Disclosure open/close must never delay keyboard access, focus movement, or reading.
- `prefers-reduced-motion` and `data-obpt-motion="reduce"` collapse non-essential shell transitions through existing tokens.
- Do not animate layout in a way that causes content jump, focus target movement, or visual-regression instability.

Source: `guides/brand-book.md` D-05; `assets/oban_powertools/tokens.css`; `.planning/REQUIREMENTS.md` MOTION-02.

## Showcase And Verification Contract

The Phase 76 showcase focal point is a complete app shell rendered with the 9-surface nav, breadcrumb, actor/context display, theme controls, and representative inner content. It must show the shell itself as the visual subject, not only the page content inside it.

| Contract | Requirement |
|----------|-------------|
| Story source | Add a separate dev/test-only `ShellStoryCatalog`; do not mix shell stories into domain stress fixtures or primitive/form catalogs. |
| Manifest | Extend the generated manifest with first-class `shell_stories` and shell targets; do not hardcode shell story ids in TypeScript. |
| Matrix | Render shell targets across themes `system`, `light`, `dark`, `high-contrast` and viewports `320`, `tablet`, `wide`. |
| Suggested targets | `shell-nine-surface-nav`, `shell-mobile-collapsed`, `shell-mobile-expanded`, `shell-active-breadcrumb`, `shell-theme-actor-context`, `shell-long-context-wrapping`. |
| VRT | Snapshot the shell header/nav/breadcrumb/theme/actor areas with real representative content. Do not mask current-route, focus, selected theme, actor/context, or nav labels. |
| Axe | Run the existing axe gate against every shell target, including collapsed and expanded mobile states where both are meaningful. |
| Behavior | Add `test/browser/specs/shell.behavior.spec.ts` to prove skip link, disclosure button, collapsed tab order, active route, breadcrumb current state, theme choice state, focus visibility, and no 320px horizontal overflow. |
| Static guards | No raw hex, no raw component spacing where tokens exist, no host selectors/theme mutation, no caller `class`/`style` escape hatch, no new runtime dependency, and no primary nav bridge entry. |

Source: `.planning/phases/76-navigation-app-shell/76-RESEARCH.md` Validation Architecture and Wave 0 gaps; existing `scripts/showcase_manifest.exs`; existing Playwright support in `test/browser/support/manifest.ts`.

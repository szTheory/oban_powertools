## Spacing Scale

Phase 80 uses the approved 4, 8, 16, 24, 32, and 48px subset of the shipped 4px-base scale. HEEx and page CSS reference tokens, not raw spacing values when a shipped token exists.

| Token | Value | Usage |
|-------|-------|-------|
| `--obpt-space-1` | 4px | Icon/text micro-gaps, status markers, compact metadata, timeline marker offsets. |
| `--obpt-space-2` | 8px | Dense table internals, label/value gaps, chip content, inline evidence/actions, compact stacked-row groups, and result-row internals. |
| `--obpt-space-4` | 16px | Narrow page/overlay inset, ordinary component internals, related filter groups, selection-summary internals, stacked form fields, and actions. |
| `--obpt-space-5` | 24px | Default section separation, surface padding, explanation-to-action rhythm. |
| `--obpt-space-6` | 32px | Wide page gutter, Jobs master/detail gutter, major section separation. |
| `--obpt-space-7` | 48px | Major showcase/page-story separation only; avoid inside tables, timelines, and result rows. |

Exceptions:

- Every interactive control exposes at least a 44px effective target, including row/page checkboxes, `Review job`, pagination, filter removal, detail close, disclosures, confirmation controls, and result recovery actions. Derive the target from token-backed min-size/padding rules.
- DataTable retains the shipped 32–36px wide/tablet visual row density while controls inside the row retain 44px targets.
- At 320px, page and full-screen detail inset is 16px. Adjacent controls retain at least 8px separation.
- The adaptive-detail breakpoint around `64rem`, 320px viewport, and 200% zoom are responsive constraints, not spacing tokens.
- Focus uses the shipped 2px outline/offset and `--obpt-color-focus`; do not create page-specific focus geometry.
- Only labelled, focusable `CodeBlock` / args / stacktrace regions may scroll horizontally. All other flex/grid children use `min-width: 0`, wrapping, or visibly signalled truncation.

## Typography

Page-owned Phase 80 typography uses exactly four sizes and two weights. Shipped components retain their approved internal typography.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Dense table metadata / secondary evidence | 13px (`--obpt-font-size-sm`) | 400 (`--obpt-font-weight-regular`) | 1.4286 (`--obpt-line-height-base`) |
| Body / table value / control / event sentence | 14px (`--obpt-font-size-md`) | 400 (`--obpt-font-weight-regular`) | 1.4286 (`--obpt-line-height-base`) |
| Section / result heading | 18px (`--obpt-font-size-xl`) | 600 (`--obpt-font-weight-semibold`) | 1.25 (`--obpt-line-height-tight`) |
| Page H1 | 28px (`--obpt-font-size-page-title`) | 600 (`--obpt-font-weight-semibold`) | 1.25 (`--obpt-line-height-tight`) |

Rules:

- Do not use weights 300, 500, 700, or heavier in Phase 80 page-owned UI.
- Each page has exactly one 28px H1. Section headings are 18px. Component-owned dialog/detail titles keep their shipped contract.
- Counts, attempts, timestamps, pagination totals, and progress numerals use sans plus `font-variant-numeric: var(--obpt-numeric-tabular)`.
- Mono is a scoped signal for complete job IDs, worker modules, queue literals, fingerprints, JSON, stacktraces, and copyable machine evidence. State labels, counts, action copy, diagnoses, guidance, source labels, reasons, and ordinary prose remain sans.
- The full worker value remains in the DOM. Compact presentation may visibly truncate or wrap it, but must not reduce it to an ambiguous module tail.
- Long English, Unicode, emoji, RTL text, and unbroken machine values wrap or use the shipped visible machine-value treatment without reducing primary data below 13px.

## Color

All values resolve through semantic `--obpt-color-*` roles in system, light, dark, and high-contrast themes. Raw hex remains confined to the primitive palette in the token layer.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--obpt-color-surface`, `--obpt-color-text` | Page background, Jobs table body, Forensics narrative/event content, primary prose. |
| Secondary (30%) | `--obpt-color-elevated`, `--obpt-color-overlay`, `--obpt-color-border`, `--obpt-color-border-strong`, `--obpt-color-muted`, `--obpt-color-subtle` | Table header and separators, filters, selection/frozen-scope summaries, adaptive review/confirmation shell, evidence limits, neutral history/provenance. |
| Accent (10%) | `--obpt-color-accent-solid`, `--obpt-color-accent-bg`, `--obpt-color-accent-border`, `--obpt-color-accent-fg`, `--obpt-color-focus` | Safe primary filters/navigation, current review/selection, active disclosure, current pagination, supported next route, and keyboard focus. |
| Destructive | `--obpt-color-danger-solid`, `--obpt-color-danger-bg`, `--obpt-color-danger-border`, `--obpt-color-danger-fg` | Cancel/discard confirmation action, failed target result, immediate error, permission-denied state, and genuine danger status only. |

Accent reserved for: `Apply filters`, `Inspect evidence`, `Review job` current state, `Open full job details`, explicit all-matching selection, current pagination, safe fresh-preview recovery, supported Forensics/Audit/native destinations, active disclosure, and focus-visible treatment.

Accent is not used for broad page chrome, every link, ordinary table rows, status meaning, provenance, evidence completeness, historical remediation, success, warning, danger, or decorative fills.

Semantic rules:

- Neutral chrome occupies roughly 90% of both pages. No gradients, broad status fills, nested-card walls, badge soup, shadow-heavy panels, or decorative motion.
- Retry uses warning intent; cancel and discard use danger intent. The mutation button and a restrained consequence marker carry the intent, not the entire dialog.
- Job state uses the shipped status taxonomy: available/scheduled neutral, executing info, retryable warning, cancelled/discarded danger, completed success.
- Bulk outcome uses distinct visible `Success`, `Skipped`, and `Failed` labels/icons. Skipped never appears as success.
- Forensics operational status, severity, provenance, and completeness are independent dimensions. A durable source is not automatically successful; partial evidence is not automatically warning-colored; historical repair is neutral evidence, not current success.
- Color is always paired with visible text plus icon, shape, border position, weight, or programmatic state.

## Cross-Page Information Hierarchy

Both pages render inside the existing `ThemeShell -> AppShell -> main#obpt-main` path. Do not instantiate another shell.

Shared hierarchy:

1. One H1 and one plain-language introductory sentence.
2. Current read/write support truth.
3. Canonical URL-owned scope controls.
4. Bounded current scan or current diagnosis.
5. One selected read-only context or one safe next route/action.
6. Freshness, frozen-scope, coverage, and completeness truth.
7. Technical chronology or immutable audit destinations.

Shared layout rules:

- Use one semantic DOM tree per page/component at every viewport. CSS and the shipped adaptive controller change geometry; never duplicate tables, details, dialogs, controls, or sensitive content for mobile.
- One local decision has one visually primary action. Secondary full-detail, Audit, Forensics, native resource, and close paths use neutral/link treatment.
- Do not put equal-weight actions above explanation. Rows are never whole-row click targets.
- Avoid nested cards. A page section may own one shared surface with semantic subsections and dividers.
- Applied URL state and invalid draft state remain visibly distinct. Current truth, historical evidence, provenance, and completeness remain visibly distinct.
- Presenters structurally redact and project finite maps before page assigns. Raw schemas, metadata, exceptions, stacktraces, reasons, tokens, and provider maps never enter generic page composition.

Source: `80-CONTEXT.md` D-02..D-08, D-54..D-57, D-73..D-80; `80-RESEARCH.md` Recommended Architecture.

| Context | Copy contract |
|---------|---------------|

| Jobs range | Exact copy such as `Showing 21–40 of 143`. |
| All-matching offer | `Select all {N} jobs matching these filters`. |
| Oversized scope | `This action is limited to {limit} jobs. Narrow the applied filters before continuing.` |
| Frozen scope | `This selection was captured at {HH:MM:SS} UTC. New matching jobs will not be included.` |

| Drifted preview | `This preview is out of date because one or more jobs changed. Create a new preview before continuing.` |

### Mutation labels and consequence copy

| Action | Intent | Confirm label | Safe dismiss | Consequence |
|--------|--------|---------------|--------------|-------------|
| Retry single/bulk | Warning | `Retry job` / `Retry {ready_count} jobs` | `Keep current state` | `Powertools requests a retry for each ready job. A retry request does not mean the job completed.` |
| Cancel single/bulk | Danger | `Cancel job` / `Cancel {ready_count} jobs` | `Keep running` | `Each ready job stops and will not retry. This cannot be undone.` |
| Discard single/bulk | Danger | `Discard job` / `Discard {ready_count} jobs` | `Keep current state` | `Each ready job is marked discarded and will not retry. This cannot be undone.` |

Every confirmation also names the exact object/scope, ready/excluded/off-page counts, reversibility/support boundary, observation time, and non-atomic execution truth before submit is available.

Copy prohibitions:

- Never render `Are you sure?`, bare `Confirm`, ambiguous `Cancel`, `Something went wrong`, `An error occurred`, `N/A`, `fixed`, `root cause` without proof, or raw `inspect(error)` output.
- Never expose raw URL key names, selector precedence, action/source atoms, preview tokens, plan hashes, task references, internal errors, provider metadata, or Ecto/query language.
- Never say a batch is atomic, exactly once, durably resumable, or complete because the browser received a final animation/state.
- Never use `Audit log` for the Forensics timeline; its heading is `Event log`.

## Interaction and Accessibility

- Use semantic HTML first: headings/sections, native table/caption/header cells, links, buttons, native checkboxes, forms/labels/hints/errors, description lists, ordered lists, time, progress, disclosure, and native dialog. Do not add ARIA grid, row-click, menu, or spreadsheet semantics.
- Each page has one H1 and a logical heading/landmark order. Jobs has one semantic table tree; Forensics has one ordered Event log.
- Every row checkbox has `Select job {id}`. The page checkbox names the current page scope. All-matching is a separate explicit control and never inferred from checkbox visual state.
- Review triggers have resource-specific names, current/expanded state, and a named controlled surface. Whole rows do not receive button semantics.
- Every interactive element is keyboard reachable/operable with visible, unobscured focus in system, light, dark, and high-contrast themes.
- Row/page selection, review, pagination, filter removal, disclosure, detail close, confirmation, and result recovery controls meet the 44px effective target.
- Color alone never carries job state, selection, scope, outcome, provenance, completeness, validation, permission, or current-versus-historical meaning.
- Form errors remain associated with their fields through programmatic invalid/described-by relationships. Invalid draft text stays visible. After invalid submit, focus the error summary or first invalid field without announcing every keystroke.
- Quick-review modality matches viewport: narrow traps/contains focus through native dialog; wide does not trap or inert. Escape/close updates canonical URL; focus returns to invoker or logical fallback.
- Confirmation is modal at every viewport. At most one dialog is active and one modal open. Quick review leaves/closes before a confirmation opens.
- Bulk progress uses native progress semantics plus processed/total text. Announce start and final result once; do not announce every target or animate a fake percentage.
- Forensics selector, event source/status, coverage, and guidance have durable accessible names. Progressive disclosure never contains sensitive hidden originals.
- Reduced motion never hides content, delays focus, or blocks action.
- Axe must report zero critical/serious issues, but connected browser evidence must also prove keyboard flow, mixed/page selection, dialog containment/restore, wide no-trap, Escape, Back/direct URLs, sparse announcements, 320px reflow, 200% zoom, reduced motion, and confidential DOM absence.

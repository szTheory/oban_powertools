# Phase 78 — UI Design Contract

> Visual and interaction contract for Phase 78 Component Groups (Meta-Components). Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | Local Oban Powertools design system: `.obpt-root`-scoped CSS custom properties in `assets/oban_powertools/tokens.css`; shadcn is not applicable. |
| Preset | Not applicable. This is an Elixir/Phoenix LiveView project with no `components.json`, Tailwind config, or shadcn registry. |
| Component library | Stateless `Phoenix.Component` function components composed from the shipped `Primitives`, `Forms`, and `DataDisplay` modules. Add exactly one public `ObanPowertools.Web.Components.OperatorPatterns` module; no stateful LiveComponents or new UI runtime. |
| Icon library | None. Reuse the closed internal status glyphs or internal decorative markup with `aria-hidden="true"`; every status and severity also has visible text. |
| Font | `--obpt-font-sans` for headings, prose, controls, result copy, and audit facts; `--obpt-font-mono` only for literal machine values and bounded technical evidence. |

The component layer is token-owned and library-scoped. No component API may accept caller `class`, `style`, raw color/size values, raw HTML, or arbitrary visual globals. Caller-provided links/actions/evidence use constrained slots; repeated filters, blockers, results, and audit facts use narrow normalized presentation maps.

## Spacing Scale

Phase 78 is explicitly constrained to the standard 4, 8, 16, 24, 32, and 48px subset of the existing Phase 71 scale. Component source and CSS reference these tokens or token-backed classes, never raw spacing literals when a token exists.

| Token | Value | Usage |
|-------|-------|-------|
| `--obpt-space-1` | 4px | Icon/text gaps, status markers, disclosure indicators, compact metadata. |
| `--obpt-space-2` | 8px | Inline actions, label/value gaps, result-row internals, tight field rhythm, and compact grouped-control gaps. |
| `--obpt-space-4` | 16px | Default component and narrow-card padding, field/action gaps, blocker/result item separation. |
| `--obpt-space-5` | 24px | Separation between explanation, impact, action, and evidence sections; dialog/drawer body padding. |
| `--obpt-space-6` | 32px | Major component sections and wide master/detail gutter. |
| `--obpt-space-7` | 48px | Major showcase separation and hit-area derivation; avoid inside dense result/audit rows. |

Exceptions:

- Every actionable control exposes at least a 44px effective target, including close, remove-filter, disclosure, and dialog actions. Derive this through token-backed CSS, not inline dimensions.
- Confirmation and detail overlays may use viewport-bound sizing and a content breakpoint around `64rem`; these are responsive constraints, not spacing tokens.
- At 320px, component padding may step from 24px to 16px, but must not fall below 16px for dialog/drawer bodies or 8px between adjacent controls.
- Focus uses the shipped 2px tokenized outline/offset and `--obpt-color-focus`; no component-specific focus geometry.
- Only bounded code/args/evidence blocks may scroll horizontally. All other children use `min-width: 0`, wrapping, or visible truncation.

Source: existing token layer; `guides/brand-book.md` D-15; `78-CONTEXT.md` D-31, D-34, D-39, D-44, D-55.

## Typography

Phase 78 uses exactly four sizes and two weights.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Supporting metadata / dense result | 13px (`--obpt-font-size-sm`) | 400 (`--obpt-font-weight-regular`) | 1.4286 (`--obpt-line-height-base`) |
| Body / controls / explanation | 14px (`--obpt-font-size-md`) | 400 (`--obpt-font-weight-regular`) | 1.4286 (`--obpt-line-height-base`) |
| Component heading / result heading | 18px (`--obpt-font-size-xl`) | 600 (`--obpt-font-weight-semibold`) | 1.25 (`--obpt-line-height-tight`) |
| Dialog / detail title | 20px (`calc(var(--obpt-font-size-xl) + (var(--obpt-space-1) / 2))`) | 600 (`--obpt-font-weight-semibold`) | 1.25 (`--obpt-line-height-tight`) |

Rules:

- Do not introduce weights 300, 500, 700, or heavier in Phase 78 UI.
- Use 20px only for the top title of a confirmation or detail surface. Nested section headings use 18px; do not create card-title escalation.
- Counts, progress, timestamps, and result totals use sans with tabular numerals. IDs, hashes, worker/module names, technical codes, and bounded evidence may use mono.
- Complete sentences and recovery guidance always use sans. Provider-shaped values never become the largest or boldest text.
- Long localized copy, Unicode, RTL text, IDs, and action labels wrap without clipping at 320px and 200% zoom.

Source: shipped token contract; Phase 74–77 typography; `guides/brand-book.md` D-13..D-15.

## Color

All visual values resolve through semantic `--obpt-color-*` roles in system, light, dark, and high-contrast themes. Raw hex remains confined to the token layer.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--obpt-color-surface`, `--obpt-color-text` | Main component bodies, explanation prose, result lists, detail content, audit content. |
| Secondary (30%) | `--obpt-color-elevated`, `--obpt-color-overlay`, `--obpt-color-border`, `--obpt-color-border-strong`, `--obpt-color-muted`, `--obpt-color-subtle` | Cards, dialog/drawer shell, filter region, section separators, metadata, neutral evidence and history. |
| Accent (10%) | `--obpt-color-accent-solid`, `--obpt-color-accent-bg`, `--obpt-color-accent-border`, `--obpt-color-accent-fg`, `--obpt-color-focus` | Safe primary actions, applied/selected state, safe links, active disclosure/selection, and keyboard focus. |
| Destructive | `--obpt-color-danger-solid`, `--obpt-color-danger-bg`, `--obpt-color-danger-border`, `--obpt-color-danger-fg` | Irreversible confirmation action, failed results, immediate errors, and danger severity only. |

Accent reserved for: `Apply filters`, safe preview/fresh-preview actions, selected row/detail trigger, safe audit/forensics/full-detail links, disclosure state, and focus-visible treatment. Accent is not used for domain status, broad overlay chrome, every interactive element, decorative fills, warning, success, or danger.

Semantic rules:

- Reversible but consequential confirmation uses warning tokens; irreversible confirmation uses danger tokens.
- Domain status and attention severity are separate. A status pill may say `Blocked` while the card's attention priority is `High`; neither value is derived from the other.
- Neutral chrome dominates AttentionCard and WhyBlocked. Severity is a restrained border/marker plus visible icon/text, never a full saturated card fill.
- `success`, `failed`, and `skipped` result rows use the shared status taxonomy and distinct visible labels/icons. Never merge failed and skipped.
- Color is always paired with text plus at least one additional non-color channel: icon, shape, border position, weight, or programmatic state.

Source: `guides/brand-book.md` D-05, D-07..D-12; `78-CONTEXT.md` D-12, D-17, D-42..D-46; Phase 74/77 semantic color contracts.

## Information Hierarchy And Layout

Every meta-component follows this fixed order when the information exists:

1. Current state.
2. Plain-language explanation.
3. Impact and exact scope.
4. Next safe action.
5. Evidence freshness and completeness.
6. Technical evidence or immutable history.

The visual anchor is the direct operator answer plus one primary next action. Technical identifiers, timestamps, codes, and payloads recede into metadata or progressive disclosure. Do not place a row of equal-weight actions above the explanation.

Shared layout rules:

- Use one component tree at every viewport. CSS and the scoped packaged controller change layout/modality; never duplicate controls or sensitive content for mobile.
- The default reading measure for explanation/recovery prose is bounded; long evidence uses `DataDisplay.code_block/1` or `args_viewer/1` rather than stretching the prose column.
- One local decision gets one visually primary action. Secondary audit, forensics, and full-detail destinations use links or neutral buttons.
- Avoid nested cards. A group may compose one Surface/Card and internal semantic sections separated by spacing/dividers.
- Maintain proximity between consequence, required reason/count, and the action they authorize.
- At 320px, action rows stack full-width in reading order; the safe dismiss/close action remains easy to reach and is not visually confused with the mutation.

Source: `78-CONTEXT.md` D-05, D-44..D-55; GROUP-02.

## Copywriting Contract

Copy is complete, grammatical, action-specific, consequence-first, and supplied by centralized presenters. Components enforce required fields and ordering; they do not fabricate sentences from action atoms, backend structs, metadata, or raw errors.

| Element | Copy |
|---------|------|
| Primary CTA exemplar | `Preview repair` |
| Empty state heading | `No jobs match the current filters` |
| Empty state body | `Clear filters or widen the time window.` |
| Error state | `Job details did not load. Retry the request or open Forensics.` |
| Destructive confirmation | `Retry 12 jobs? Powertools requests a retry for each job, including jobs outside this page. A retry request cannot be undone and does not mean the job completed.` |

Required exact or pattern copy:

| Context | Contract |
|---------|----------|
| Reason label | `Reason` |
| Reason hint | `Explain why this action is needed. Do not enter secrets.` |
| Bulk count label | `Type 12 to confirm` where `12` is the frozen authoritative count. |
| Safe dismiss exemplar | `Keep current state` or the more specific `Keep running`; never generic `Cancel` when the mutation verb is Cancel. |
| Action label | Verb plus named object/count, for example `Retry 12 jobs`, `Pause cron entry`, or `Discard job`. Never bare `Confirm`. |
| Pending | `Retrying 12 jobs…` plus `This action has been accepted and can no longer be canceled.` when the state is non-dismissible. |
| Success receipt | `Retry requested for 12 jobs. Audit evidence recorded.` only when both facts are authoritative. |
| Partial result | `Retry requests finished with mixed results. Review failed and skipped jobs before trying again.` |
| Drifted preview | `This preview is out of date because the job changed. Create a new preview before retrying.` |
| Expired preview | `This preview expired. Create a new preview before continuing.` |
| Consumed preview | `This preview was already used. Create a new preview to run the action again.` |
| Filter draft | `Changes not applied.` |
| Filter disclosure | `Filters (3 applied)` with the current applied count. |
| Filter submit | `Apply filters` |
| Filter clear | `Clear filters` |
| Filter result status | Exact summary such as `42 jobs match the applied filters.` |
| Detail loading | `Loading job details` |
| Detail unavailable | `Job details are unavailable. Refresh the job or open Forensics.` |
| Detail permission | `Job details unavailable — requires operator role.` |
| Attention question | Human title and direct summary answering `What needs attention?` without literally rendering that question as boilerplate. |
| Blocker heading | `Why this workflow is blocked` |
| Evidence unknown | `Current blocker evidence is unknown. Refresh the workflow before acting.` |
| Audit reason missing | `No operator reason recorded` |
| Audit outcome missing | `Outcome not recorded` |

Copy prohibitions:

- Never render `Are you sure?`, bare `Confirm`, ambiguous `Cancel`, `Something went wrong`, `An error occurred`, `N/A`, `fixed`, or raw `inspect(error)` output.
- Say `current blocker` or `current cause`, not `root cause`, unless causality is proven.
- Distinguish empty, stale, unavailable, permission-denied, partial, and unknown. Never render `No blockers` from incomplete evidence.
- A receipt states what Powertools requested, changed, or durably recorded. It never claims host work completed unless the authoritative result proves it.
- AuditEntry uses an immutable complete sentence, visible absolute time, and explicit missing-field copy. A later outcome is a later entry.

Source: `guides/brand-book.md` D-16..D-21; `78-CONTEXT.md` D-07, D-10..D-19, D-29..D-30, D-45..D-53; COPY-02.

## Shared Component API And Ownership

`ObanPowertools.Web.Components.OperatorPatterns` exports exactly:

```text
confirm_action_dialog/1
filter_bar/1
detail_surface/1
attention_card/1
audit_entry/1
why_blocked/1
```

Shared contract:

- All six are stateless Phoenix function components with closed `attr` values and constrained named slots.
- Parent LiveViews own authorization, data loading, open state, form/change state, URL grammar/history, preview generation, frozen scope, execution, progress, redaction, result normalization, durable audit writes, and navigation.
- Components consume presentation-ready sentences and finite maps. They never accept Ecto schemas, exceptions, raw action atoms, preview tokens, plan hashes, secret originals, or backend payloads.
- Required map values are fetched from finite atom/string aliases without dynamic atom creation. Unknown keys never become DOM attributes.
- Primitives own leaf controls, Forms owns fields, DataDisplay owns status/tables/descriptions/timeline/progress/code/args/empty/toast rendering.
- No page migrations, new routes, saved filters, filter DSL, bulk executor, audit schema expansion, causal inference, or new operator capability belongs in this phase.

Source: `78-CONTEXT.md` D-01..D-08 and Phase Boundary.

| Root | One restrained overlay surface with 20px title, consequence-first prose, visible scope block, form/result region, and separated safe/mutation actions. Use `role="dialog"`, not blanket `alertdialog`. | Wrap with `Phoenix.Component.focus_wrap`; set `aria-modal="true"`, `aria-labelledby`, and `aria-busy` only while submitting. | Preview | Order: named object -> exact scope/count including off-page membership -> consequence -> reversibility -> support boundary -> reason/count fields -> actions. | Reason / count | Render `Forms.textarea` for the required reason and `Forms.input` for exact frozen bulk count when present. | Pending | Replace action affordance with one named busy message; use spinner or real progress, never both for the same work. | Partial / failed / skipped | Keep the dialog open. | Success | Component normally leaves the DOM; parent emits exactly one existing Toast/Flash receipt. | Pop/restore focus. All-success bulk closes only when returned count equals frozen scope. |
| Dismiss / restore | Safe action is neutral and labeled by retained state; mutation action is action-specific and warning/danger. | Dismissible states close on Escape and visible dismiss. ## Interaction And Accessibility

Required Phase 78 behavior:

- Semantic HTML first: native dialog, form, button/link, article, list, description list, time, status region, and details. Do not add ARIA menu/grid semantics.
- All controls are keyboard reachable/operable and visibly focusable in all four themes. Close, filter-removal, disclosure, and dialog actions meet the 44px target.
- ConfirmActionDialog traps focus, initializes focus on structured static content, closes dismissible states on Escape, and restores invoker/fallback focus.
- DetailSurface is modal only when drawer/full-screen. Wide inline detail never traps focus or makes the background inert.
- Filter disclosure keeps `aria-expanded`, visibility, and tab order synchronized and uses the same DOM at all widths.
- Live-region messages are restrained and exact: one result-summary announcement after applied filters, one details-loaded announcement when useful, one success receipt, and one explicit result heading focus for partial/failed confirmation results. Do not announce every keystroke.
- Static AttentionCard has no alert role. Immediate errors use alert semantics only when they require timely attention; ordinary current state/history remains non-live.
- No state relies only on color. Visible text and icon/shape/programmatic semantics carry status, severity, selection, validation, and outcome.
- Secret/redacted originals are absent from text, attributes, titles, hidden disclosures, URLs, copy buffers, logging, and telemetry.
- At 320px and 200% zoom, action rows stack, fields and long prose wrap, detail becomes full-screen, and there is no page horizontal overflow or duplicate tree.

Axe is necessary but insufficient. Connected browser tests must prove focus trap/restore, inertness, Escape, resize mode switching, URL/history behavior, duplicate submit suppression, disclosure keyboard behavior, live message exactness/cardinality, direct-link fallback, and absence of nested dialogs.

Source: A11Y-02; `78-CONTEXT.md` D-20..D-22, D-31, D-35..D-40, D-43, D-55..D-61.

## Motion

| Motion Token | Contract |
|--------------|----------|
| `--obpt-motion-duration-fast` | Hover/focus/selected/disclosure feedback and compact result-state emphasis. |
| `--obpt-motion-duration-base` | Drawer/dialog appear/dismiss transform/opacity feedback only. |

| `--obpt-motion-ease-enter` / `--obpt-motion-ease-exit` | Overlay enter/exit only when origin and interruption remain truthful. |

Rules:

- Motion is feedback, never decoration. No ambient, looping, auto-advancing, or layout-reordering animation.

- `prefers-reduced-motion` and `data-obpt-motion="reduce"` collapse transform/opacity transitions to the existing instant token without hiding state, backdrop, focus, or content.
- Keyboard interaction is not animated, and motion is never required to understand a state change.

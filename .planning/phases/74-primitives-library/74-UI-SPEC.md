## Spacing Scale

Declared values use the existing Phase 71 token scale. Components must reference tokens or token-backed classes, never raw spacing literals in primitive source.

| Token | Value | Usage |
|-------|-------|-------|
| `--obpt-space-1` | 4px | Icon gaps, inline metadata gaps, tight label/icon spacing. |
| `--obpt-space-2` | 8px | Compact control padding, badge padding, segmented-control gaps. |
| `--obpt-space-4` | 16px | Default component padding, card/surface padding, standard vertical rhythm. |
| `--obpt-space-5` | 24px | Section spacing, modal/surface body padding, larger primitive matrix gaps. |
| `--obpt-space-6` | 32px | Wide showcase/page padding and major grouped primitive spacing. |
| `--obpt-space-7` | 48px | Major section separation only; avoid inside compact primitives. |

Exceptions:

- Icon-only buttons must expose a minimum 44px interactive hit target. Implement this through a token-backed min-size/hit-area class, not raw component px.
- The `320px` viewport is a test target, not a spacing token. Primitive stories must fit without horizontal page overflow at 320px.
- Focus treatment uses the existing tokenized focus color and the project focus-ring pattern; do not add per-primitive custom focus geometry.

Source: `guides/brand-book.md` D-15; `assets/oban_powertools/tokens.css`; `.planning/REQUIREMENTS.md` A11Y-03 and COMP-04.

## Typography

Use exactly these Phase 74 primitive type roles. Other existing token sizes remain available to legacy/showcase code, but new primitive source should stay inside this table unless a later phase expands the contract.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px (`--obpt-font-size-md`) | 400 (`--obpt-font-weight-regular`) | 1.4286 (`--obpt-line-height-base`) |
| Label | 13px (`--obpt-font-size-sm`) | 600 (`--obpt-font-weight-semibold`) | 1.25 (`--obpt-line-height-tight`) |
| Caption / Kbd | 12px (`--obpt-font-size-xs`) | 600 (`--obpt-font-weight-semibold`) | 1.25 (`--obpt-line-height-tight`) |
| Stat value / primitive heading | 18px (`--obpt-font-size-xl`) | 600 (`--obpt-font-weight-semibold`) | 1.25 (`--obpt-line-height-tight`) |

Rules:

- Use only weights 400 and 600 in new primitive UI. Do not introduce 300, 500, 700, or heavier weights for Phase 74 primitives.
- Metrics use sans text with `--obpt-numeric-tabular`; do not switch numbers to mono.
- Mono is reserved for `Kbd`, IDs, hashes, queue names, worker/module names, cron expressions, and other literal machine values.

Source: `guides/brand-book.md` D-13..D-15; `assets/oban_powertools/tokens.css`.

## Color

Components must reference semantic `--obpt-color-*` roles only. Raw hex remains confined to the token layer.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--obpt-color-surface` with `--obpt-color-text` | Root surface, primitive backgrounds where no elevation is needed, story cells that should recede. |
| Secondary (30%) | `--obpt-color-elevated`, `--obpt-color-border`, `--obpt-color-muted` | Card/Surface, neutral Button, Divider, Badge neutral tone, showcase story cells, secondary text. |
| Accent (10%) | `--obpt-color-accent-solid`, `--obpt-color-accent-bg`, `--obpt-color-accent-border`, `--obpt-color-accent-fg` | Safe primary Button, Link/navigation emphasis, active selected control, focus treatment. |
| Destructive | `--obpt-color-danger-solid`, `--obpt-color-danger-bg`, `--obpt-color-danger-border`, `--obpt-color-danger-fg` | Danger Button, destructive examples, error messaging, danger StatusPill only. |

Accent reserved for: safe primary actions, navigation links, selected state affordances, and focus treatment. Accent must not be used for warning, danger, success, decorative fills, broad background chrome, or every interactive element.

Semantic tones:

| Tone | Token family | Reserved for |
|------|--------------|--------------|
| `neutral` | surface/elevated/border/muted | Default metadata, neutral Badge/Tag, neutral Button. |
| `info` | `--obpt-color-info-*` | Contextual status only; never a primary action. |
| `success` | `--obpt-color-success-*` | Completed/healthy status only. |
| `warning` | `--obpt-color-warning-*` | Reversible caution such as pause-like operations or retryable status. |
| `danger` | `--obpt-color-danger-*` | Destructive, irreversible, error, discarded, or terminal failure states. |

Color cannot be the only signal. StatusPill/Badge stories must include visible text and, where useful, icon/shape differences in addition to tone.

Source: `guides/brand-book.md` D-05, D-07..D-12; `.planning/phases/74-primitives-library/74-CONTEXT.md` D-13..D-16; `assets/oban_powertools/tokens.css`.

## Copywriting Contract

Primitive stories use real operator-console wording, not decorative samples.

| Element | Copy |
|---------|------|
| Primary CTA | `Retry job` |
| Empty state heading | `No primitive stories registered` |
| Empty state body | `Add token-backed primitive stories before updating visual baselines.` |
| Error state | `Primitive stories did not load. Regenerate the showcase manifest and check the primitive story registry.` |
| Destructive confirmation | None implemented in Phase 74. Danger Button examples may use `Cancel job` or `Discard job`, but must be inert story examples; confirmation behavior is deferred to Phase 78. |

Copy rules:

- Button and Link labels use verb plus noun: `Retry job`, `Cancel job`, `View audit log`.
- Loading copy names what is loading: `Loading job history`, not `Loading...`.
- Disabled-with-reason copy names the requirement: `Cancel job - requires operator role`.
- Error copy names the recovery path. Do not use `Something went wrong`.
- Destructive primitive examples must not execute a mutation from the showcase.

Source: `guides/brand-book.md` D-16..D-21; `.planning/phases/74-primitives-library/74-CONTEXT.md` D-23..D-28.

## Primitive Contracts

| Primitive | Visual Contract | Interaction / A11y Contract |
|-----------|-----------------|-----------------------------|
| Button | Closed variants: `neutral`, `primary`, `warning`, `danger`, `ghost` only if needed by existing flows. Primary uses accent; danger uses danger; warning uses warning; neutral uses elevated/border. | Render semantic `<button>` by default. Support native `disabled` when no explanation is needed. For disabled-with-reason, keep the control perceivable with `aria-disabled="true"`, suppress action events, and expose the reason through text or description. |
| IconButton | Square visual treatment, minimum 44px target, decorative icon hidden from assistive tech. | Require `label` at API level and render an accessible name independent of tooltip text. Tooltip may mirror the label, but cannot be the accessible-name source. |
| Link | Text/navigation emphasis only; accent can identify navigation but not mutation. | Wrap Phoenix navigation/link affordances. Links navigate; buttons act. Do not use a link-styled element for `phx-click` mutations. |
| Badge / Tag / StatusPill | Non-interactive metadata/status. Closed tones: `neutral`, `info`, `success`, `warning`, `danger`. Visible label required. | Must not look clickable. StatusPill accepts visible label, tone, optional decorative icon, size, and accessible prefix text. Full domain status taxonomy is deferred to Phase 77. |
| Card / Surface | Restrained structural containers with variants `plain`, `elevated`, `inset`, and `attention` only if needed by the 9 pages. No decorative nested card stacks. | Surfaces are structural, not interactive by default. If a future surface becomes interactive, it must use a native interactive element or an explicit later-phase pattern. |
| Divider | Tokenized border-only separator. Use neutral border. | Use semantic `<hr>` only when it separates content meaningfully; use `aria-hidden="true"` for purely visual separators. |
| Spinner | Small bounded action/section progress only. Uses motion tokens and a visible or screen-reader label. | No bare spinners. Use `role="status"` or equivalent live status when appropriate. Require named context such as `Loading job history`. |
| Skeleton | Progressive loading for regions/tables/cards, never for indefinite unknown work. | Pair with named loading state and `aria-busy` on the owning region when content is refreshing. Reduced motion must keep the shape visible. |
| Tooltip | Text-only, non-interactive, tokenized surface. No rich hovercards, menus, popovers, forms, or links. | Opens on hover and focus, dismisses on `Escape`, leaves focus on trigger, and uses `aria-describedby` or equivalent relationship. |
| Kbd | Mono, compact, neutral/elevated treatment for literal keys only. | Use for shortcuts/keyboard literals, not as a status badge. Text remains readable at 320px. |
| Stat | Label plus value with tabular sans numerics and optional trend/status text. | Value updates must avoid digit jitter. If color indicates direction/severity, include text/icon/shape as the second signal. |

API rules:

- Primitive components live in a narrow Powertools-owned module such as `ObanPowertools.Web.Components.Primitives`.
- Use `attr/3`, `slot/3`, closed `:values`, sensible defaults, and `attr :rest, :global` for caller-owned `id`, `phx-*`, `aria-*`, `data-*`, and narrowly necessary native attributes such as `form`.
- Filter or reject caller `class` and `style` on primitives. Visual variants are component-owned and token-backed.
- Parent LiveViews own state, authorization, events, and mutation flows.

Source: `.planning/phases/74-primitives-library/74-CONTEXT.md` D-01..D-16 and D-23..D-27; `.planning/phases/74-primitives-library/74-RESEARCH.md`.

## Interaction And Accessibility

Required behavior for Phase 74:

- Semantic HTML first. Add ARIA only when native semantics are insufficient.
- Every interactive primitive is keyboard reachable, keyboard operable, and has visible `:focus-visible` styling through the focus token.
- Focus treatment must remain visible in light, dark, high-contrast, and system themes.
- Color is never the sole signal. Status and severity require visible text and at least one additional channel where useful.
- Disabled controls that need an explanation remain perceivable and reachable through `aria-disabled` plus event suppression. Native `disabled` is acceptable only when no reason needs to be reached.
- Tooltip open/dismiss behavior, icon-button accessible names, reduced-motion behavior, and no horizontal overflow at 320px require targeted Playwright checks beyond axe.
- Primitive story cells must be inspectable at 320px, tablet, and wide without page-level horizontal scrolling. Use `min-width: 0`, wrapping, and visible truncation where content can be long.

Not proven by Phase 74:

- Dialog focus trap/restore, full page keyboard traversal, complete manual screen-reader announcement quality, 200% zoom/reflow closure, and final cross-page copy/motion audit remain Phase 82 or later-phase responsibilities.

Source: `.planning/REQUIREMENTS.md` A11Y-02..A11Y-04 and COMP-03..COMP-04; `guides/visual-regression-and-a11y.md`; `.planning/phases/74-primitives-library/74-CONTEXT.md` D-23..D-28.

## Motion

| Motion Token | Contract |
|--------------|----------|
| `--obpt-motion-duration-fast` | Hover/focus/pressed feedback for primitives. |
| `--obpt-motion-duration-base` | Tooltip appear/dismiss and bounded loading feedback when needed. |
| `--obpt-motion-duration-slow` | Avoid for primitives unless a later phase proves it is necessary. |
| `--obpt-motion-ease-standard` | Default primitive transition easing. |

Rules:

- Motion is feedback only: hover, focus, appear/dismiss, progress, or origin-aware feedback where feasible.
- No ambient, looping decorative animation. Spinner/skeleton motion is permitted only for named loading states.
- `prefers-reduced-motion` and `data-obpt-motion="reduce"` must collapse non-essential transition duration through existing tokens without hiding content.
- Primitive CSS must use motion tokens only; no inline timings in components or stories.

Source: `guides/brand-book.md` D-05; `assets/oban_powertools/tokens.css`; `.planning/REQUIREMENTS.md` MOTION-02.

## Showcase And Verification Contract

Primitive stories are required production-quality audit targets, not placeholders.

| Contract | Requirement |
|----------|-------------|
| Story source | Add a separate dev/test-only primitive story registry. Do not append primitive-only stories to `ObanPowertools.ShowcaseCatalog.scenarios/0`. |
| Manifest | Generate one unified Playwright manifest from catalog scenarios plus primitive stories. Do not hardcode primitive target lists in TypeScript. |
| Matrix | Every primitive target renders across themes `system`, `light`, `dark`, `high-contrast` and viewports `320`, `tablet`, `wide`. |
| Target IDs | Use stable IDs such as `primitive-button-matrix`, `primitive-icon-button-accessible-names`, `primitive-status-pill-tones`, `primitive-surface-card-density`, `primitive-tooltip-open`, `primitive-spinner-skeleton-loading`, and `primitive-kbd-stat-values`. |
| VRT | Snapshot real primitive cells only. Do not snapshot placeholders or future components. Do not mask meaningful pixels such as tone colors, focus rings, labels, icons, or dense metric values. |
| Axe | Run existing axe gate against primitive story targets and open-state variants where applicable. |
| Behavior tests | Add targeted Playwright checks for icon-button names, focus visibility, tooltip hover/focus/Escape behavior, 320px overflow, and reduced-motion loading/transition behavior. |
| Static guards | Add primitive-specific source/render guards for no raw hex, no raw component px where a token exists, no host selectors, and no caller `class`/`style` escape hatch. |

Source: `.planning/phases/74-primitives-library/74-CONTEXT.md` D-17..D-22 and D-27; `test/browser/support/manifest.ts`; `scripts/showcase_manifest.exs`; `guides/visual-regression-and-a11y.md`.

## Out Of Scope

- Form controls, filter chips, combobox tags, and field validation primitives.
- App shell/navigation patterns.
- Data tables, empty-state component, toast/flash, progress bar, redaction viewer, and full status taxonomy.
- ConfirmActionDialog, danger forms, drawers, rich popovers, hovercards, menus, and "Why blocked?" meta-patterns.
- Page migration across the 9 LiveViews.
- Broad host-facing UI kit support promise.

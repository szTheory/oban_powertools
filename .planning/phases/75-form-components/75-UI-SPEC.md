# Phase 75 - UI Design Contract

> Visual and interaction contract for Phase 75 form components. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | Local Oban Powertools design system: `.obpt-root`-scoped CSS custom properties in `assets/oban_powertools/tokens.css`; shadcn is not applicable. |
| Preset | Not applicable. This is an Elixir/Phoenix LiveView project with no `components.json`, Tailwind config, or shadcn registry. |
| Component library | Stateless `Phoenix.Component` function components over `Phoenix.HTML.FormField` and `to_form`; no Radix, Base UI, JavaScript widget library, or new runtime dependency. |
| Icon library | None. Errors and selection states use visible text and native control affordances; any decorative icon is internal and `aria-hidden`. |
| Font | `--obpt-font-sans` for labels, controls, hints, errors, and values; `--obpt-font-mono` only when a field displays literal machine values. |

## Spacing Scale

Form CSS and components must use the existing token scale; no raw spacing literals in component source.

| Token | Value | Usage |
|-------|-------|-------|
| `--obpt-space-1` | 4px | Inline label markers, checkbox/radio internal gaps, tight error-prefix gap. |
| `--obpt-space-2` | 8px | Label-to-control, control-to-hint/error, compact choice and choice-label spacing, control vertical padding. |
| `--obpt-space-4` | 16px | Control horizontal padding, default gap between fields, and FieldGroup item spacing. |
| `--obpt-space-5` | 24px | Separation between form sections or grouped fieldsets. |
| `--obpt-space-6` | 32px | Major showcase matrix grouping only. |
| `--obpt-space-7` | 48px | Page-level separation only; not inside controls. |
| Phase contract maximum | 64px | Reserved for page-level whitespace outside form components; no current form component uses it. |

Exceptions:

- Checkbox, radio, and switch labels must provide a minimum 44px effective hit target, including compact row-selection treatment. Implement through token-backed CSS, not raw component pixels.
- Text inputs, selects, and textareas must remain comfortably operable and must not shrink below their intrinsic native control height.
- At the 320px test viewport, controls use `width: 100%`, `max-width: 100%`, `min-width: 0`, and wrapping choice labels; no page-level horizontal overflow.
- Focus geometry follows the existing tokenized two-pixel outline/offset pattern already used by `.obpt-input`; extend the selector contract to all Phase 75 controls.

Source: existing token layer; `75-CONTEXT.md` D-17, D-24..D-26; `REQUIREMENTS.md` COMP-04 and A11Y-03.

## Typography

Use exactly these form roles and only weights 400 and 600.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Control value / body | 14px (`--obpt-font-size-md`) | 400 (`--obpt-font-weight-regular`) | 1.4286 (`--obpt-line-height-base`) |
| Label / legend | 13px (`--obpt-font-size-sm`) | 600 (`--obpt-font-weight-semibold`) | 1.25 (`--obpt-line-height-tight`) |
| Hint / optional marker | 12px (`--obpt-font-size-xs`) | 400 (`--obpt-font-weight-regular`) | 1.6 (`--obpt-line-height-relaxed`) |
| Error | 13px (`--obpt-font-size-sm`) | 600 (`--obpt-font-weight-semibold`) | 1.4286 (`--obpt-line-height-base`) |

Rules:

- The close 12/13/14px progression is retained deliberately because these are the locked existing project tokens and Phase 75 may not introduce one-off type sizes. Hierarchy comes from the combined system: controls/body are 14px regular; labels/legends and errors are 13px semibold; hints are 12px regular with the more open 1.6 line height and muted color. Size, weight, line height, color, and placement together create a clear distinction without expanding the design system.
- Labels and legends are always visible and semibold; placeholders never replace them.
- Error text is field-specific and readable, not an icon-only or color-only mark.
- Machine values may use mono, but ordinary queue labels, option labels, and numeric inputs remain sans; numeric values may use tabular numerals.
- Long labels, hints, errors, values, and option copy wrap without clipping at 320px.

Source: brand typography contract; `75-CONTEXT.md` D-07, D-09, D-11, D-17.

## Color

Components reference semantic `--obpt-color-*` roles only. Raw hex remains confined to the token layer.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--obpt-color-surface`, `--obpt-color-text` | Input/select/textarea backgrounds, editable values, default form surface. |
| Secondary (30%) | `--obpt-color-elevated`, `--obpt-color-border`, `--obpt-color-muted`, `--obpt-color-subtle` | Field groups, borders, hints, read-only and disabled differentiation. |
| Accent (10%) | `--obpt-color-accent-solid`, `--obpt-color-accent-bg`, `--obpt-color-accent-border`, `--obpt-color-accent-fg`, `--obpt-color-focus` | Focus rings, checked native choices, and the on-state of an immediate reversible switch. |
| Destructive | `--obpt-color-danger-fg`, `--obpt-color-danger-bg`, `--obpt-color-danger-border` | Visible validation messages and invalid control/group borders only; no destructive action is implemented. |

Accent reserved for: keyboard focus, checked checkbox/radio state, and the explicit on-state of an immediate reversible switch. Neutral editable controls do not use accent merely because they are interactive.

State rules:

- Invalid uses danger border/background/text plus visible `Error:` text and `aria-invalid="true"`; color is never the sole signal.
- Disabled is visibly muted and uses native `disabled`; it need not be submitted. If explanation is required, associate perceivable descriptive text.
- Read-only remains high contrast and selectable, uses native `readonly` where supported, retains its value for submission, and removes hover/pressed affordance rather than looking disabled.
- Required status appears in text (`Required`) or an explained marker; optional fields may say `Optional`. Never communicate required state by color alone.
- All roles must resolve in system, light, dark, and high-contrast themes without component-local theme overrides.

Source: `75-CONTEXT.md` D-07..D-12, D-16, D-24; token semantic roles.

## Copywriting Contract

Form stories use realistic operator-console language and recovery-oriented messages.

| Element | Copy |
|---------|------|
| Primary CTA | `Apply filters` |
| Empty state heading | `No form stories registered` |
| Empty state body | `Add token-backed form stories before updating visual baselines.` |
| Error state | `Form stories did not load. Regenerate the showcase manifest and check the form story catalog.` |
| Destructive confirmation | None in Phase 75. Destructive confirmation and required-reason flows are deferred to Phase 78. |

Field-copy examples:

| Element | Required copy |
|---------|---------------|
| Text label | `Worker name` |
| Search/filter label | `Search jobs` |
| Hint | `Enter a full or partial worker module name.` |
| Required marker | `Required` |
| Optional marker | `Optional` |
| Validation error | `Error: Enter a worker name.` |
| Recovery error | `Error: Reason must be at least 10 characters. Add more detail and try again.` |
| Disabled explanation | `Queue selection is unavailable while this job is running.` |
| Read-only explanation | `Job ID is assigned when the job is inserted and cannot be changed.` |
| Radio legend | `Job state` |
| Explicit clear option | `Any state` |
| Switch label | `Pause queue processing` |

Rules: use sentence case; name the field or action; do not expose raw backend errors; do not use `Something went wrong`; loading copy names what is pending; switch labels name the setting rather than saying only `On` or `Off`.

Source: brand voice D-16..D-21; `75-CONTEXT.md` D-11..D-12, D-15..D-16, D-24.

## Form Component Contracts

| Component | Visual Contract | Interaction / Accessibility Contract |
|-----------|-----------------|--------------------------------------|
| Input | Full-width token-backed control; types text, search, email, and number share one restrained treatment. Filter variant may add search affordance without changing semantics. | Normal API is `field={@form[:name]}`. Derive id/name/value/errors. Require non-empty visible label. Plain search remains `type="search"`, never `role="combobox"`. |
| Textarea | Same surface/border/focus/error language as Input; vertical resize remains available; long content wraps. | Associated visible label, hint/error ids, and native read-only/disabled behavior. Do not auto-grow with a JavaScript dependency. |
| Select | Native select styled consistently with other controls; do not hide the native indicator unless an equally robust token-owned replacement exists. | Preserve native keyboard and mobile semantics. Placeholder option is not a label. Include explicit `Any state`/`None` when clearing is valid. |
| Checkbox | Native checkbox with label-aligned 44px effective target; checked state uses accent plus native mark. | Named boolean form fields emit Phoenix-style hidden unchecked values. Event-driven row selection does not emit hidden unchecked values. Label click toggles control; accessible name is mandatory. |
| RadioGroup | Fieldset block with semibold legend, stacked/wrapping choices, group-level hint/error. | Render native radios within `fieldset`/`legend`. Do not preselect without a real default. Arrow-key and label-click behavior remain native. Group error is described by the group/choices. |
| Switch | Checkbox-backed track/thumb visual, visible label naming the setting, textual state where context needs it. | Use only for immediate reversible settings. Space toggles the native checkbox. Do not use switch styling for delayed-submit boolean fields. Color is not the only on/off signal. |
| FieldGroup | Restrained structural grouping with 16px item rhythm and 24px separation from adjacent groups; no decorative card nesting. | Use `fieldset`/`legend` when grouping related choices; otherwise semantic wrapper plus heading/description. Group-level described-by ids are stable. |
| Label | Visible, semibold, wraps naturally; required/optional annotation is adjacent and textual. | `<label for>` must match the final caller-overridden or field-derived control id. Placeholder never substitutes. |
| Hint | Muted, readable text directly associated with its field/group. | Stable `${id}-hint`; merge into caller `aria-describedby` without overwriting or duplicating ids. |
| Error | Danger text with explicit visible or screen-reader-safe `Error:` prefix; positioned after control/hint consistently. | Stable `${id}-error`; render only when eligible/explicit; set `aria-invalid="true"` only while the error is rendered; merge description ids. |

API rules:

- Components live in `ObanPowertools.Web.Components.Forms`, separate from `Primitives`.
- Components are stateless; parent LiveViews own changesets/maps, `to_form`, validation events, URL state, authorization, and persistence.
- Use closed values and explicit attrs. Permit caller `id`, `name`, `value`, `form`, `placeholder`, `autocomplete`, `required`, supported `phx-*`, `aria-*`, `data-*`, debounce/throttle, and control-relevant native attrs.
- Filter or reject caller `class` and `style`; visual variants are component-owned and token-backed.
- Use `used_input?/1` for changeset-backed interaction timing where applicable. Explicit submit/action errors may override timing when the parent has attempted the action.
- Caller-provided `aria-describedby` tokens come first, followed by generated hint and error ids, deduplicated and space-separated.

Source: `75-CONTEXT.md` D-01..D-21; `75-RESEARCH.md` field-first and description/error patterns.

## Interaction And Accessibility

- Every high-level control has a visible programmatic label or fieldset legend; every input is keyboard reachable and uses native keyboard behavior.
- Visible `:focus-visible` treatment applies to text controls, selects, textareas, checkboxes, radios, and switches in every theme.
- Hints and errors use deterministic ids derived from the final control/group id. Caller descriptions are merged, never replaced.
- Validation stays quiet before interaction when `used_input?/1` applies. When shown, error text precedes recovery guidance and `aria-invalid` is truthful.
- Choice controls preserve native semantics. Do not add custom roles, roving tabindex, active descendant, or popup ARIA.
- Disabled, read-only, required, invalid, pending, checked, and switch on/off states are distinguishable through text/shape/semantics as well as color.
- Pending/loading controls remain legible, use `aria-busy` on the owning region where appropriate, and prevent duplicate action in the parent without replacing the field value with a spinner.
- At 320px, labels and options wrap, controls fit their container, field groups stack, and no horizontal page overflow occurs.
- Phase 75 targeted browser checks must prove label click, label/legend association, described-by merging, invalid timing, focus visibility, keyboard choice operation, disabled/read-only distinction, reduced motion, and 320px overflow. Axe alone is insufficient.

Not proven here: full page traversal, dialog focus trap/restore, complete manual screen-reader announcement quality, 200% zoom/reflow closure, and cross-page copy/motion audit remain Phase 82 work.

## Motion

| Motion Token | Contract |
|--------------|----------|
| `--obpt-motion-duration-fast` | Border/background/track/thumb feedback for hover, focus, checked, invalid, and switch state. |
| `--obpt-motion-duration-base` | Avoid by default; permitted only for bounded pending feedback that remains comprehensible without motion. |
| `--obpt-motion-ease-standard` | Default form transition easing. |

Rules:

- Form motion is feedback only. No ambient, looping, or auto-advancing animation.
- Never animate layout, hint/error height, or validation copy in a way that delays reading or moves focus targets.
- `prefers-reduced-motion` and `data-obpt-motion="reduce"` collapse non-essential transitions through existing tokens.
- Native control state remains immediately visible even when transition duration is reduced to the instant token.

## Showcase And Verification Contract

The primary showcase focal point is one complete field stack rendered at realistic width. Its fixed visual hierarchy is **visible label or legend -> control -> hint -> validation message**. In the default story the control is the anchor through border, surface, and value contrast; in focus stories the focused control and its accent focus ring are the anchor; in invalid stories the invalid control plus its immediately following `Error:` message are the anchor. Supporting state matrices remain secondary and must not visually compete with this field stack.

| Contract | Requirement |
|----------|-------------|
| Story source | Add a separate dev/test-only form story catalog analogous to `PrimitiveStoryCatalog`; do not mix form stories into domain stress scenarios. |
| Manifest | Extend the generated manifest with first-class form targets; do not hardcode story ids in TypeScript. |
| Matrix | Cover valid, invalid, required, optional, disabled, read-only, pending, filter-ready, long label/value, and 320px wrapping states across system, light, dark, and high-contrast themes. |
| Suggested targets | `form-input-states`, `form-textarea-select`, `form-checkbox-modes`, `form-radio-group`, `form-switch-states`, `form-validation-wiring`, `form-disabled-readonly`, `form-filter-ready`, `form-long-content`. |
| VRT | Snapshot real rendered form controls and state matrices; do not mask focus, error, checked state, labels, or long content. |
| Axe | Run the existing axe gate against every form target and all meaningful invalid/disabled/open state variants. |
| Behavior | Prove label click, fieldset/legend, merged descriptions, truthful invalid state, checkbox hidden-value modes, radio/switch keyboard behavior, focus visibility, and 320px overflow. |
| Static guards | No raw hex, no raw component spacing where tokens exist, no host selectors/theme mutation, no caller class/style escape hatch, and no new runtime dependency. |

## Out Of Scope

- Combobox/typeahead popups, async suggestions, multiselect, chips, saved filters, and filter grammar.
- `FilterBar` and other grouped operator meta-components.
- Destructive-action forms, required-reason/confirm flows, bulk count-to-confirm, and `ConfirmActionDialog`.
- Migration of the nine operator pages onto these components.
- Page-owned validation/business logic, URL persistence, authorization, mutation, or persistence.
- Broad host-facing UI kit or form schema DSL.

Source: Phase 75 boundary and Deferred Ideas in `75-CONTEXT.md`.

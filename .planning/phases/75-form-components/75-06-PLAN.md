<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| caller assigns -> HEEx | Labels, hints, errors, ids, values, and rest attrs cross from caller-owned data into component-rendered HTML. |
| native browser state -> visible UI | Checkbox checked state changes in the browser before a LiveView/server rerender. |
| hidden form inputs -> submitted params | Hidden unchecked values can alter server params during unrelated form submissions. |
| generated DOM ids -> assistive tech | `aria-describedby` depends on ids being unique and complete. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-75-06-01 | Spoofing | `switch/1` visible state | mitigate | Render both state labels and use CSS tied to the native checked state, with browser tests for both toggle directions. |
| T-75-06-02 | Tampering | `checkbox/1` and `switch/1` hidden unchecked inputs | mitigate | Disable hidden false inputs whenever the visible named boolean control is disabled, proven by render and browser markup tests. |
| T-75-06-03 | Information Disclosure | duplicate error ids and incomplete descriptions | mitigate | Generate unique ids for multiple errors and include all visible error ids in `aria-describedby`, with duplicate-id browser checks. |
| T-75-06-04 | Tampering | caller attrs and form text | mitigate | Preserve existing visual-safe rest filtering and HEEx escaping while adding only targeted behavior changes. |
| T-75-06-05 | Denial of Service | aggregate visual gate residuals | accept | Existing scenario-only VRT drift is outside this gap scope; executor records residual evidence without changing unrelated baselines. |

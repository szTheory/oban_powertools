## Must Haves — Decision Coverage

- **D-31:** Use a compact global DataTable plus one URL-owned AuditEntry inside DetailSurface, never a global card timeline or connected rail.
- **D-32:** Keep row facts finite and human-labelled with an explicit resource-specific View evidence control and an independent target link.
- **D-33:** Render the selected record as immutable past-tense evidence with complete redaction-safe reason, explicit outcome, and absolute UTC labelled Recorded at.
- **D-34:** Render exact missing-value copy and never fabricate correlation, causality, outcome, or current state from IDs, keys, suffixes, or adjacent records.
- **D-35:** Preserve exact URL-owned resource_type/resource_id/event_type meanings as human applied filters and add none of the deferred search/export/filter features.
- **D-36:** Replace unbounded retrieval with stable 20-row Previous/Next pagination ordered inserted_at DESC, id DESC while retaining filters and reachability.
- **D-37:** Keep Repair evidence retention restrained, read-only, and explicitly distinct from live table rows and unsupported completeness claims.
- **D-38:** Structurally allowlist row/detail facts after DisplayPolicy so raw metadata, secrets, tokens, hashes, credentials, exceptions, and stacktraces never enter render channels.
- **D-39:** Keep Audit visibly/semantically read-only and neutral, with no bulk/action/refresh/urgency UI or historical causality/current-state claim.

## Artifacts this phase produces

- New public query symbol `ObanPowertools.Audit.fetch_in_scope/3` with arguments `(filters, id, opts)` and result `{:ok, %Audit{}} | :error`; it filters by primary key and the exact active three-filter scope in one bounded SQL query.
- New public Phoenix function component `ObanPowertools.Web.AuditLive.page_content/1`, shared by `render/1` and later deterministic page stories; it performs no query, authorization, current-time lookup, URL parsing, or mutation.
- New semantic IDs: `audit-page`, `audit-retention`, `audit-filters`, `audit-records`, `audit-record-{id}`, `audit-detail`, and `audit-entry-{id}`.
- New parent assigns: `audit_page`, normalized `event_rows`, `filter_form`, normalized `active_filters`, `result_summary`, `selected_event_id`, `selected_detail`, and `detail_state`; raw event schemas/metadata are not retained in render assigns.
- New LiveView event names: `apply_filters`, `select_event`, and `close_detail`. There are no mutation, bulk, selection-checkbox, export, auto-refresh, or live-tail events.
- Canonical URL order: `resource_type`, `resource_id`, `event_type`, optional nondefault `page`, optional `event`. Default page 1 is omitted. Applying/removing/clearing filters resets page to 1 and removes event.
- Exact pagination summary format: `Records {first}–{last} of {total} · Page {page} of {max(total_pages, 1)}`; empty scopes use `0 records · Page 1 of 1`.
- Filter form namespace/fields: `filters[resource_type]`, `filters[resource_id]`, and `filters[event_type]`; no actor/free-text/date/export/facet/query-grammar field is added.
- Selected-detail absence strings and `Recorded at` label come from the Phase 79 presenter/shared component foundation; no new schema fields are invented.
- No migration/index, mutation, policy, route, stream, infinite-scroll, provider adapter, stateful LiveComponent, packaged JavaScript, or dependency is added.

## Must Haves — Decision Coverage

- **D-17:** Use DataTable plus the URL-owned selected DetailSurface; entry name is the explicit selection control and row Actions/kebab controls are removed.
- **D-18:** Keep the selected detail as the sole mutation venue with current context first, safely stacked controls, and server-derived disabled reasons where useful.
- **D-19:** Preserve the preview, reason, confirm, result server workflow while making detail and confirmation mutually exclusive and restoring selected context after dismissal/recovery.
- **D-20:** Use warning intent and the exact action-specific confirm/dismiss labels for pause, resume, and run-now.
- **D-21:** Render exact consequence/non-effect truth for each action and never claim an accepted or recorded run-now request ran.
- **D-22:** Require a trimmed nonblank UI reason with no-secrets help and server revalidation while preserving the compatible public Cron API contract.
- **D-23:** Authorize before preview and immediately before execution with the current principal while preserving durable identity, expiry, drift, single-use, plan, overlap, transaction, and Audit authority off-DOM.
- **D-24:** On clean success reload truth and emit exactly one truthful receipt plus Audit destination; keep recoverable results open with a safe draft and explicit fresh-preview path.
- **D-25:** Start focus on the labelled consequence, contain and conditionally dismiss the dialog, restore logical focus, and keep loading disable distinct from concurrency authority.

## Artifacts this phase produces

- New public Phoenix function component `ObanPowertools.Web.CronLive.page_content/1`, shared by `render/1` and later deterministic page stories; it performs no query, authorization, mutation, current-time lookup, or URL parsing.
- New semantic IDs: `cron-page`, `cron-entries`, `cron-entry-{safe-id}`, `cron-entry-detail`, `cron-confirmation`, and `cron-receipt`; fallback IDs derive from the existing stable entry identity with URL-safe encoding, not raw HTML interpolation.
- New parent assigns: `confirmation_form`, `confirmation_state`, `confirmation_result`, `confirmation_open?`, `detail_open?`, and `receipt`; existing `entries`, `selected_entry`, `history_summary`, `preview`, and `read_only?` remain server-owned.
- New LiveView event names: `close_detail`, `open_pause_confirmation`, `open_resume_confirmation`, `open_run_now_confirmation`, `validate_confirmation`, `submit_confirmation`, `dismiss_confirmation`, `create_new_preview`, and `dismiss_receipt`. Raw backend action atoms/tokens/hashes are not event params or DOM attributes.
- Confirmation form namespace/field: `confirmation[reason]`; exact hint `Explain why this action is needed. Do not enter secrets.` and exact blank error `Enter a reason before continuing.`
- Closed confirmation states supplied to the shared component: `:preview`, `:submitting`, `:partial`, `:failed`, `:expired`, `:drifted`, and `:consumed`; clean success is represented by dialog removal and one receipt.
- Exact action labels/dismiss labels/consequences are those in UI-SPEC D-20/D-21; all use `intent: :warning`.
- No change to `lib/oban_powertools/cron.ex`, `reason_required: false`, RepairPreview schema, Ecto migration, authorization policy, route macro, provider adapter, or packaged JavaScript.
